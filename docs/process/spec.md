> **江戸の絵本に図と歌だけが残る玩具について、学ぶ人が予想を先に書き、仮説ごとの紙の型紙を刷って作り、試した事を順位も成否の言葉も付けずに記録し、人の説明を先に受けてから次の版が出る輪が、まっさらな環境で動き、その型紙で作った物が実物で動く事。**

### エンジンが持つ物

| 物 | ファイル | 約束 |
|---|---|---|
| 寸法 → 配置 | `compose.py` の `compose(template_id, params, source, page, version, title, inject)` | 返り値は（混ぜた寸法、配置、落ちた床の一覧）。範囲で落ちたら配置は作らない |
| 配置 → SVG・PDF・PNG | `render.py` | 判断を持たず描くだけ |
| 刷る入口 | `python -m omochae`（`__main__.py`） | 終了は 0 = 通る / 3 = 床に落ちた / 4 = 検査できない |
| 床 | `floors.py`、`marks.py` | F1.marks・F2.bom・F5.*（印字域・重なり・物理・絵・画像の数） |
| 雛形 | `templates/slider_fan.py`、`templates/pivot_counterweight.py`、`fan_model.py`、`pivot_model.py` | 雛形は ID・DEFAULTS・RANGES・check_range・check_physics・parts・bom・materials・title・place を持つ |
| 出典の値 | `data/sources/*.json` の書誌の値 | toy・所蔵・永続 ID・改変・出典 ID を印にする |
| 試験 | `tests/frozen/scenarios`・`run_floors.py`・`test_fan_model.py`・`test_pivot_model.py`、基準は F1・F2・F5 | |

## 5. 確かめの手順（凍結とまっさらな環境）

**作戦のスケジュール（本人、11-04）**: 〜11-05 小さい実装を揃えて組み合わせる（機能の凍結は 11-05）→ 11-05 夜〜11-06 レビューと評価（sol のレビュー、まっさらな環境での確認。この節の手順を使う）→ 11-06〜11-07 直しは止めた所だけ、デモ動画の準備 → 11-07 撮影 → 11-08 17:00 提出（締切 20:00）。


```
git clone https://github.com/akihidem/utsushi.git && cd utsushi
./init.sh                      # 足りない物を名指しして 4 で止まる
./run.sh                       # 46 本が期待どおり（11-04 昼）。結果は out/RESULT.md
PYTHONPATH=src .venv/bin/python -m web.play_server   # http://127.0.0.1:8766/ で入口 A
```

- 型紙を手で刷るには予想が先に要る。試しで刷る時は、使い捨ての置き場に仮の予想を書く: `OMOCHAE_DATA=<使い捨ての場所> PYTHONPATH=src .venv/bin/python -m omochae.hypotheses predict "仮の予想"` の後に `... hypotheses print H-A --out <出す場所>`
- 原図の写し（`out/sources/*.jpg`）は git の外。まっさらな clone では画面の図と、手順の紙の完成のイメージが出ない（どちらも無い時の形で動く）。取り込みは `python -m omochae.ingest`
- 提出の床: 受け皿の道具の submit-check（この repo の外）。11-04 昼に残る FAIL はデモ動画のリンクと非公開の 2 つ（U-19・U-20・U-24）
- 凍結の判定に使う物: 上の 3 行が通る事、2 の各条件の「状態」、6 の決まっていない点のうち凍結の前に要る物

まだ確かめていない事: 本物の API、本物のスマホ、人が画面を使う事、v8 の実物の組み立て、虎の完成。
