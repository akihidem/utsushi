# J-029 作成の過程の動画を試行の記録に結び、型紙の版まで回す

- **状態**: 本人の指示（2026-11-05、窓口を通して届いた）。Issue #216。仕組みは作った。本人の動画での 1 周はこれから
- **本人の言葉**: 本人が作成の過程を動画で撮っている。その動画をフィードバックの仕組みに入れて、実際に型紙が改善するかを見たい
- **対象**: まず必須 2 種（御来迎 goraigo-v10・虎 tora-v3）の今回の試行

## 流れ

```
動画 → 記録 R-NNNN に結ぶ（音と撮影情報を落とす）→ 止まった候補（機械）→ 札（何秒・手順・種類・一言。読みの案）
→ 人が札を確かめる → 人の説明 → 直しの案 D-NNNN（確かめた札が根拠）→ 人が採る → 次の版
→ 版ごとの止まり方を手順ごとに並べる（次の試行と比べる）
```

作る側の頁（玩具ごとの様子の頁の「動画から版まで」）で 1 本につながって見える。学ぶ人の頁には、版と直した所だけが出る（札の字と映像は出ない）。

## 守る線

| 線 | どうしたか |
|---|---|
| 動画は git の外 | 記録の置き場の media の下。記録と番号で結ぶ。元のファイルには触らない |
| 声と撮影情報 | 音と撮影情報（位置など）を落として写す。映像は作り直さない（J-022） |
| 顔 | 人が動画ごとに「顔と声が入っていない」と確かめるまで、作る側の頁にも映像とコマを出さない。学ぶ人の頁・ギャラリー・合言葉なしの場には、確かめた後も出さない |
| 人が採る | 札は読みの案で、人が確かめた札だけを数える。人の説明の前に案を作れない。案は人が採るまで版にならない（J-013・F9）。命令の側は端末の床（AI や自動の処理が「本人」と名乗れない）、本人は頁のフォームから |
| 検査 | 寸法の案は今の輪を通す（F7 の向きの検査。落ちれば版にならない） |
| 凍結の床 | 今の版の紙を変えない。寸法の直しは仮説の版 2 以降、形や手順の文の直しは雛形の次の版（goraigo-v11・tora-v4）で、雛形を直すのはエンジンの側（J-026）。雛形の直しの記録 T- は、直した組と commit が無いと残せない（まだ直していない案を、直した事にしない） |
| 成績にしない | 効いたかは判定しない。数件の比べなので、手順ごとの数を並べて人が読む（J-025） |

## 止まった候補をどう拾うか

1 秒に 1 コマを小さな灰色にして隣のコマとの差を見る。差の少ない区間が 20 秒以上続いた所を候補に挙げる。映像は外へ出さない。候補は「手が止まったかもしれない所」で、考えている時もカメラの外で作業している時も同じに見える。札を付けるのは人か、コマを読んだ Claude で、どちらも案。

## 比べた案

| 論点 | 採った案 | 捨てた案と理由 |
|---|---|---|
| 受け口 | 手元の命令で結ぶ | 手帖の「上げる」: 1 つ 20MB までで作成の過程の動画は入らず、学ぶ人の頁とギャラリーに出てしまう |
| 札の付け方 | 人が確かめる案 | 動画を丸ごと AI に渡して確定: 人が採る線を崩す。映像を外へ出す量も増える |
| 置き場 | git の外 | repo に入れる: 決まりに反する。大きさの点でも |
| 雛形の直しの出口 | 確かめた札をエンジンの報告の形で書き出す | サイトで雛形を直す: 入口と道具はエンジンの側の決定（J-026）に反する |

## 使い方

```
python -m omochae.trial_video attach <動画> --source <印> --hypothesis H-A --result 動いた --tried-on 2026-11-05
python -m omochae.trial_video sheet R-0003 <一覧の画像> --every 30    # 読むための一覧
python -m omochae.trial_video mark R-0003 --at 123 --step 8 --kind fold --note "…" --read-by "読んだ人"
python -m omochae.trial_video propose R-0003 --marks M1,M2 --text "…" --by 作る側 --param fold_count --to 20
python -m omochae.trial_video report R-0003 --built yes --finish 3 --minutes 40   # エンジンの報告の形
```

札の確かめ・顔と声の確かめ・案の採否は、作る側の頁のフォームから（端末があれば confirm・drop・show-ok・adopt・reject の命令でも）。

## 確かめていない事

- 本人の動画での 1 周（動画が届いてから）。作り物の動画で、命令と頁の両方の道を通した。
- 長い動画（数 GB）を読む時間。iPhone の HEVC の映像の再生。
- 止まった候補の当たり具合（作り物の動画でしか見ていない）。
- 数件の比べで何が言えるか。版の効き目は、次の版の試行が要る。
