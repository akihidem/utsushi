- **状態**: 本人の指示と決定（2026-11-05、窓口を通して届いた）。Issue #216。仕組みは作った。本人の動画での 1 周はこれから
- **食い違いあり・本人が決める**（11-06）: 下の流れの「人が札を確かめる」は、11-06 の本人の方針（札は事前の人の確かめなしで束に入れる。PR #449）と合っていない。流れの文はまだ直していない
- **本人の言葉**: 本人が作成の過程を動画で撮っている。その動画をフィードバックの仕組みに入れて、実際に型紙が改善するかを見たい
- **対象**: まず必須 2 種（御来迎 goraigo-v10・虎 tora-v3）の今回の試行

## 流れ

```
動画 → 記録 R-NNNN に結ぶ（音と撮影情報を落とす）→ 止まった候補（機械）→ 札（何秒・手順・種類・一言。読みの案）
→ 人が札を確かめる → 人の説明 → 直しの案 D-NNNN（確かめた札が根拠）→ 人が採る → 次の版
→ 版ごとの止まり方を手順ごとに並べる（次の試行と比べる）
```

札の字と映像は、学ぶ人の頁に出ない。

## 守る線

| 線 | どうしたか |
|---|---|
| 動画は git の外 | 記録の置き場の media の下。記録と番号で結ぶ。元のファイルには触らない |
| 声と撮影情報 | 音と撮影情報（位置など）を落として写す。H.264 と HEVC は絵を作り直さず、流れの中の付帯情報（SEI）も落とす。ほかの形は作り直す（MJPEG はコマごとに EXIF を持てる。J-022） |
| 大きさと長さ | 写す大きさと長さに上限を付け、写せた中身を数える。同じコマを何度も指す動画、長さを偽った動画、中身の無い動画を結ばない |
| 顔 | 人が動画ごとに「顔と声が入っていない」と確かめた印を持つ。学ぶ人の頁・ギャラリー・合言葉なしの場には、確かめた後も出さない。動画とコマを返す道は置かない |
| 人が採る | 札は読みの案で、人が確かめた札だけを数える。人の説明の前に案を作れない。案は人が採るまで版にならない（J-013・F9）。命令の側は端末の床（AI や自動の処理が「本人」と名乗れない）、本人は頁のフォームから |
| 検査 | 寸法の案は今の輪を通す（F7 の向きの検査。落ちれば版にならない） |
| 凍結の床 | 今の版の紙を変えない。寸法の直しは仮説の版 2 以降、形や手順の文の直しは雛形の次の版（goraigo-v11・tora-v4）で、雛形を直すのはエンジンの側（J-026）。雛形の直しの記録 T- は、直した組と commit が無いと残せない（まだ直していない案を、直した事にしない） |
| 成績にしない | 効いたかは判定しない。数件の比べなので、手順ごとの数を並べて人が読む（J-025） |

## 本人の決定（11-05）

1. 顔や声が入った動画は、映像を頁に出さず、札の字だけで回してよい。声は取り込みで必ず落とす。
2. 動画のコマを読むのは Claude でよい。読むのは作業の中で切り出したコマだけにし、動画そのものを外に置かない（J-022 の観察の補助の範囲）。

## カメラの目的（本人の言葉 11-05）

> カメラで見るのはそういうとこだよ

> 型紙は不完全でうまく動かないけどそれを人間が工夫で乗り切る過程をAIにフィードバックして型紙が改善される

カメラで見るのは、不完全な型紙（AI の仮説）を人が工夫で乗り切る過程で、人の出来を測るためではない（窓口の説明）。札の種類に「人の工夫」を足した。人の工夫の札は止まった手順に数えず、エンジンへの報告では「そのほか」に「工夫:」の印を付けて渡す（エンジンの形は変えない）。札に人の上手下手を書かない。

## 止まった候補をどう拾うか

1 秒に 1 コマを小さな灰色にして隣のコマとの差を見る。差の少ない区間が 20 秒以上続いた所を候補に挙げる。映像は外へ出さない。候補は「手が止まったかもしれない所」で、考えている時もカメラの外で作業している時も同じに見える。札を付けるのは人か、コマを読んだ Claude で、どちらも案。

## 比べた案

| 論点 | 採った案 | 捨てた案と理由 |
|---|---|---|
| 受け口 | 手元の命令で結ぶ | 手帖の「上げる」: 1 つ 20MB までで作成の過程の動画は入らず、学ぶ人の頁とギャラリーに出てしまう |
| 札の付け方 | 人が確かめる案 | 動画を丸ごと AI に渡して確定: 人が採る線を崩す。映像を外へ出す量も増える |
| 置き場 | git の外 | repo に入れる: 決まりに反する。大きさの点でも |
| 雛形の直しの出口 | 確かめた札をエンジンの報告の形で書き出す | サイトで雛形を直す: 入口と道具はエンジンの側の決定（J-026）に反する |

## 使い方

```
python -m omochae.trial_video attach <動画> --source <印> --hypothesis H-A --result 動いた --tried-on 2026-11-05
python -m omochae.trial_video sheet R-0003 <一覧の画像> --every 30    # 読むための一覧
python -m omochae.trial_video mark R-0003 --at 123 --step 8 --kind fold --note "…" --read-by "読んだ人"
python -m omochae.trial_video propose R-0003 --marks M1,M2 --text "…" --by 作る側 --param fold_count --to 20
python -m omochae.trial_video report R-0003 --built yes --finish 3 --minutes 40   # エンジンの報告の形。動いたかが記録に無い時は、人が見て --moved を付ける
```

札の確かめ・顔と声の確かめ・案の採否は、端末で人が打つ（confirm・drop・show-ok・adopt・reject の命令）。

## 専用の受け口（本人の指示 11-05、#337）

本人の指示: 『江都二色』の再現の経験がある大人の教え子から動画を受け取る。合言葉付きのリンクで開く専用の頁で、ブラウザから複数上げる。自動で撮影情報を外し、この入口と同じ処理を通して、各玩具のたたき台の改善の輪へ回す。上げた人に受け取りが見える。もう 1 つ、作る前の型紙のレビューの動画を受ける口も作る（本人の指示 20:35）。

```
頁（合言葉 → Cookie）→ 小分けで送る → 受付番号 → 1 本ずつ: つなぐ → 入れ物の頭と読みの確かめ → 記録 → attach（音と撮影情報を落とす）→ コマの一覧 → 元を消す
→ ここから上の流れと同じ（札は読みの案、人が確かめる、人の説明、案、人が採る）
声は、元を消す前に非公開で写し、この機械の中で字にする → 字にしたら、その場で声を消す → 作る側のセッションが字とコマを読んで札の案を書く → 人が確かめる
```

| 線 | どうしたか |
|---|---|
| 見せる物 | サイトの道に足さず、別のサーバにした。ほかの頁は無い。合言葉が無いと立たない。口は手元だけで、外からはトンネルだけが入る |
| 残す物 | 受付・おもちゃ・文・状態だけ。ファイルの名前・番地・機器は残さない。ログも書かない |
| 動画でない物 | MP4 と MOV の頭だけを通し、読み手を決め打って読む。読めない物は記録を作らず、元も消す |
| 機械の都合の失敗 | 道具が止められた時や場所が足りない時は、元を消さずに回し直す。相手のファイルのせいにしない。回数で止める |
| 声 | 作る時の動画の口もレビューの口も、字にするまで非公開で残し、字にしたらその場で消す（作る時の口は本人の決定 11-06 でレビューと同じ形に。消す合図は窓口の決定 11-06 夜。前は整理が終わってから手の命令で消す形で、命令を待つ間に声が残り続けた）。字にするのは手元のモデルで、外へ送らない。字にする道具（`requirements-asr.txt`）が無い機械では、口を立てない（同じ窓口の決定）。字の前に手で消す命令は断る（`--force` の時だけ消す） |
| 札 | 字は言い直して札に書く。そのままの文を頁や Issue に写さない。名前は機械で落とせないので、人が確かめる |
| 取り下げ | 受付番号から、動画・声・字・コマ・札・文を消す。案の根拠になった記録は番号だけ残す |
| 誰の動画か | 18 歳以上で、子どもが映っていない物だけ。映っている人の許しと一緒に、送る時に確かめる（今週は子どもの記録を集めない） |
| 頁の文 | 本人が採った（11-05）。試験が文字列で見る。声を消す時の 1 文だけ、窓口の決定（11-06 夜）で「整理が終わったら消します」を「字にしたら消します」に替えた |

比べた案:

| 論点 | 採った案 | 捨てた案と理由 |
|---|---|---|
| 頁の置き場 | 別の小さなサーバ | サイトの道に足す: 相手に記録と写真の頁も開く。手帖の「上げる」: 1 つ 20MB までで、ギャラリーに出る |
| 大きな動画 | 8MiB の小分け | そのまま送る: トンネルの 1 回の送信の上限（100MB）を越える。外の置き場: 相手に Google へ入る事を求め、名前とメールが残る |
| 処理の時 | 受付の後に 1 本ずつ | 返事の前: つなぐ・読むに数分かかり、トンネルの待ち時間（100 秒）を越える |
| 札 | 人か Claude が読んで案を付ける | 止まった候補をそのまま札にする: 止まった事に意味を付けない決まりに反する。サーバから AI を呼ぶ: 常駐しない決まりに反する |

## repo の外の受け口から移す（本人の指示 11-05、#337）

教え子の動画は、repo の外の受け口が受け取る。受け取った物は `python -m omochae.trial_video take-in <置き場>` でこの入口の記録へ写す。

| 線 | どうしたか |
|---|---|
| 学ぶ人の頁 | 記録に受け口の印（`via`）を付け、`records.all_records` が既定で外す。`loop.confirmed_records` とサイトの記録の口でも外す |
| 動いたか | 受付に選んだ結果があれば持ってくる。無ければ「わからない」で受ける（雛形の札に無くても、受け口の記録だけ）。動いたと数えない |
| 声とファイルの名前 | 移さない。声は受け口の置き場に残る。字にするかは本人の決定を待つ |
| 映像 | 写し直す。受け口の写しに残った流れの中の情報も落ちる |
| 札 | 案は案のまま、人の確かめは確かめたまま移す |
| 回し直し | 移した受付の表を持ち、同じ受付を 2 回移さない。元の置き場は変えない |

## 確かめていない事

- 本人の動画での 1 周（動画が届いてから）。作り物の動画で、命令の道を通した。
- 札を確かめる作る側の頁は載せていない。端末が無い人は札を確かめられない。
- 長い動画（数 GB）を読む時間。iPhone の HEVC の映像の再生。
- 止まった候補の当たり具合（作り物の動画でしか見ていない）。
- 数件の比べで何が言えるか。版の効き目は、次の版の試行が要る。
