## 作り込んだ物（11-03 夜）

試験の 1 回目を無駄にしないための物を先に作った。どれも本物の API は呼ばない。

| 物 | 中身 | なぜ |
|---|---|---|
| 送る物の下見 | `hypotheses generate --dry-run` と `words ... --dry-run`。呼ぶ直前で止め、送るはずの指示・道具・材料を JSON に書き出す。画像は大きさだけ。1 回の費用の上限と今日の上限を出す | 本人が承認の前に、何をどう送るかを見られるようにする |
| 下見で見つけた不具合の修正 | `generate` が、本人が採らなかった歌の読み（複写 A の「怠らし」）も Claude に渡していた。採らなかった読みは渡さないようにした | 採られなかった語を根拠に仮説を立てさせないため。図鑑の引用の候補から外したのと同じ線 |
| キャッシュ | 指示と道具の定義の終わりに目印、伸びる会話に自動の目印 | 1 回の生成で道具の往復ごとに図を送り直すので、入力の費用が重なる |
| 費用の数え方 | キャッシュの書き込み（1.25 倍）と読み出し（Opus 5.5 は 0.05 倍）を数える | キャッシュを入れると、入力の数はキャッシュの外の残りだけになり、数えないと費用を少なく見積もる |
| SDK を通した試験 | `tests/test_agent_sdk.py`。本物の SDK に手元の偽の送り先をつなぎ、送る形（ベータの見出し、フォールバック、思考、キャッシュの目印）と、費用の記録を確かめる | 偽の client の試験だけでは、SDK が引数を受けるかが分からない |
