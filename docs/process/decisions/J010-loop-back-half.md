# J-010 輪の後半: 記録 → 解釈 → 次の手 → 人の採否

- **状態**: 作った。Claude の API は本物では 1 回も呼んでいない（試験は記録した形の偽物）。実際の試行の記録もまだ無い

## 流れ

```
記録 → 解釈の案（Claude）→ 人が確定 → 次の手の案（Claude: 版の変更・順位・新しい仮説・測る事）→ 人が採る → 版 2 を刷る → 次の案が前例として引く
```

人が確定しない解釈は根拠に使えず、前例にも出ない。確定の前に Claude を呼ばない。

## 比べた案

| 論点 | 採った案 | 捨てた案と理由 |
|---|---|---|
| 輪の書き方 | Messages API の tool use を自分で書く | Tool Runner: 便利だが、道具 8 回・やり直し 2 回で必ず止める制御を自分で持ちたい。Managed Agents: 短い輪で人の確認に戻る形に合わない |
| 結果の受け方 | `submit_result` の道具と自前の検査 | 道具の強制はこのモデルで使えない。自由な文は検査できない |
| 鍵が無い時 | 人が解釈と変更を書けば同じ道と同じ検査で輪が閉じる | 鍵を必須にする: 持たない人が輪に入れない（`research/04` の Q5） |
| 変更の向きの確認 | 雛形の式で数え直す（F7） | Claude の見込みをそのまま使う: 向きの間違いが素通りする |
| 変えてよい寸法 | 雛形ごとに絞る | 全部開ける: 仮説の違いと寸法の違いが混ざる |
| 順位 | 人が採った時だけ変える | 記録の数で自動で並べる: 少ない記録で答えのように見える |

## 守りの限界

- 人の確認は端末で番号を打つ操作で、AI を止める補助。完全な保証ではない。
- 仮説の採否（H3）と型紙の確定（H4）は、人が仮説を選んで刷る操作で代えていて、確定の記録はまだ無い。
- 図の読みや解釈の質は、本物の API で試すまで分からない。
