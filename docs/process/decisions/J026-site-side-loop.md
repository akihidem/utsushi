# J-026 改善の輪はサイト側でも回す（報告を型紙の改善に回し、次に作る人に直した版を渡す）

- **状態**: 本人の方針（2026-11-05 朝、窓口を通して届いた。「これはハッカソン本編の話」）
- **本人の言葉**: 「作ったものの感想と動きを報告してもらったら、サイト側もループを回し、型紙の改善をする。そうすることでより良いおもちゃの型紙を提供できる」
- **窓口の補足**: 型紙の洗練（完成度・動きの完成度）は、この報告を材料に進めるのが本筋

## 何が変わるか

[J-010](J010-loop-back-half.md) の輪の後半（記録 → 説明 → 読み → 人が採る → 次の版）は、試した人が自分の次の版を作る輪として作ってあった。今回の方針は、その輪を**サイト側**が回す事。報告は 1 人の次の版のためだけでなく、型紙そのものを良くし、**次に作る人**が直した版を受け取る。

| 段 | 前 | 後 |
|---|---|---|
| 報告 | 動きの札（結果）と、困った所の答え | 動きの札に、感想の欄（自由な文、空でもよい）を足した |
| 刷る | 仮説の札の「刷る」は常に版 1 | 一番新しい版（報告から直した版）を刷る。版 1 しか無ければ版 1 |
| 報告の版 | 記録は常に版 1 への返事 | 刷ってある一番新しい版への返事として残る |
| 見える形 | 窓の版の札と、版ごとの根拠の 1 行 | 玩具の頁に「型紙の改善の輪」の節（どの報告がどの版を変えたか・次の版を待つ報告・説明を待つ報告）。サイト側の一覧 /loop |
| 案 | 人が寸法と値を書く。鍵があれば Claude の読み | 変えない（機械が案を出す道具はエンジンの側の受け持ち。下の「受け持ちの分け方」） |

## 受け持ちの分け方（本人の決定、11-05 朝。カード 20261105-090458 の (b)）

報告から**型紙そのもの（雛形）**を直す輪は、報告の入口も道具もエンジン（paper-to-toy）の側が受け持つ。推しは「入口はサイト、道具はエンジン」（a）だったが、本人が (b) に決めた。

| 物 | 受け持ち |
|---|---|
| 雛形の直し（寸法の床・組み方の文・部品の形）の材料になる報告の入口、報告の形・検査・集計 | エンジン |
| 学ぶ人の試した記録と感想、仮説ごとの版（寸法を 1 つ変えた次の版）、どの記録がどの版を変えたかの表示 | サイト（この repo。J-010 の輪の続き） |
| 直った雛形を受け取り、次に作る人に渡す | サイト（取り込みは統括の担当） |

この決定で、サイトの側で作りかけた「報告から寸法の案を機械が出す道具」は入れなかった（枝 lane/suggest に残した。エンジンの側が使うかを決める）。上の表の「案」の行は、サイトでは人が書く形のまま。全種の型紙を目で検めた結果（research/28）は、エンジンの報告の言葉に寄せて書き、エンジンの側へ渡す。

## 守る線（変えない）

- 人の説明が先（J-013）。説明の無い報告は「説明を待つ報告」で、次の版に使わない。
- 採るのは人（F9.human）。機械の案も Claude の案も、人が採るまで版にならない。
- 順位と成績を出さない（J-025）。輪の節と /loop に出すのは、報告の数・版の数・変えた寸法・根拠の記録だけ。「何件動いた」は出さない。
- 版は答えではない。報告をもとに直した翻案で、紙で動いても昔の作り方の証明にはならない。

## 比べた案

| 論点 | 採った案 | 捨てた案と理由 |
|---|---|---|
| 次に作る人に渡す版 | 一番新しい版を刷る | 版を選ばせる: 最初に選ぶ物が増える。古い版は窓の版の札から開ける |
| 輪の置き場 | 既にある台帳（data/loop の版の記録）を画面に出す | 別の「改善の台帳」を作る: 根拠の線が 2 本になる |
| サイト側の一覧 | /loop（学ぶ人の頁からは道を置かない。道を知っている作る側が開く） | 頭の帯や序から入る: 学ぶ人の順路に、作る側の作業台と集計が混ざる（検品の指摘で、序からの道も外した） |
| 感想の扱い | 記録の欄（impression）に入れ、連絡先の形は床で落とす | 別の投稿にする: 動きの報告と離れ、どの版への感想か分からなくなる |

## 確かめていない事

- 人が報告して、サイト側が採り、次の人が直した版で作る、の一周を人で回した確認。
- エンジンの側の報告の入口と、サイトの記録のつなぎ方（サイトの記録をエンジンの報告の形で渡すかは未決）。
- 感想の文が増えた時の読み方（今は記録ごとに 1 つずつ読む）。
