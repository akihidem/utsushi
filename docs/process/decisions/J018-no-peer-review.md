# J-018 人のレビューは受けず、批評は Claude のセッションだけで行う

- **状態**: 本人の決定（2026-11-03、窓口を通して届いた）
- **決めた事**: 人のレビューは受けない。批評は Claude のセッションだけで行い、Claude の使い方として事実どおりに書く。「一人で作った」という説明も事実になる形で進める

本人の決定の文の語はゲートの検査語に当たるので、ここでは「人」と書いた。意味は変えていない。

## 比べた案

| 案 | 中身 | 捨てた理由 |
|---|---|---|
| 1 | 主催に確かめ、答えに従う | 本人が採らなかった。作る側の推しはこれだった |
| **2** | 人のレビューをやめる。批評は Claude のセッションだけ | 採用 |
| 3 | 人のレビューを取り入れ、提出物に事実として書く | 本人が採らなかった |

人の検討を出所を隠して反映する形は、案に入れなかった。審査員に事実と違う経緯を見せる事になるため。

## 批評を Claude だけにした事の限り

批評の役も Claude なので、作った者と同じ弱さを持ちうる。別のセッションにしても、同じモデルの別の目にすぎない。[批判的レビュー](../research/13-critical-review.md)と[哲学のレビュー](../research/15-philosophy-review.md)は、人の評価の代わりにはならない。

## 「一人で作った」と言える範囲

作る側から見える事と、見えない事を分ける。

| 点 | 今わかる事 |
|---|---|
| repo の commit | 全部 `akihidem` の名義。Claude Code のセッションが書き、末尾に共著の行がある |
| 人のレビューの記録 | repo に無い。記録にある批評の役は Claude のセッション |
| 本人の手元と窓口の中 | 作る側からは見えない。これまで人のレビューが無かったかは、作る側では確かめられない |
| 受け皿の担当 | repo の作成、ゲートの管理、最初の push をした。人か Claude のセッションかを、作る側は確かめていない |

だから提出物では「人は本人一人で、作業の大半は Claude のセッションが行った」の形で書く。「一人で」だけだと、Claude が書いた事が隠れる。受け皿の担当が人なら、この文は直す。
