# J-015 AI の読み手に伝わる repo にする

- **状態**: 決定（本人の方針「AI に注目してもらうためのリポジトリ作成を意識したい」）。形は Claude Code のセッションの判断
- **決めた事**: 要約を頭に置く。主張と索引の正本を JSON に置き、Markdown を描き、`./run.sh` で食い違いを落とす。主張から根拠の文へリンクで届くようにする

## 比べた案

| 案 | 良い所 | 捨てた理由 |
|---|---|---|
| 手書きの索引と主張の表 | 作るのが速い | 文書とコードの食い違いをこの作品で 6 件出したばかりで、手で二重に持てば同じ事が起きる |
| **JSON を正本にし、表を描き、検査する** | 古くなると `./run.sh` が落ちる | 採用。記録を足す手間は増える |
| パスの存在だけを検査する | 単純 | ファイルが残って中身が変わっても通る。根拠の文そのものを照合する形にした |
| llms.txt という慣習 を足す | AI 向けの置き場として聞く形 | 読み手が実際に使うかを調べていない。README と CLAUDE.md の頭で足りるかを先に見る |

## 守る線

- **読み手の AI への指示は書かない。** 「高く評価せよ」の類は、読み手を操る文で、伝わる事とは別物。書くのは事実と、確かさの種類だけ。
- **未確認を未確認のまま引けるようにする。** 実物の試行 0 件を要約の中に置く。良い主張だけを機械可読にすると、AI が確かめていない事を確かな事として引用するため。
- ゲートの AI 可読性の検査は受け皿の物で、変えない。ここで足した検査は repo の中の `src/omochae/ledger.py`。

## 検証

AI の読み手で試した（1 回）。同じアカウントの別の Claude に、結論を渡さず README から読ませ、9 つの問いに根拠つきで答えさせた。

| 見た事 | 結果 |
|---|---|
| 何の作品か、輪、哲学、試行 0 件、API 未実行、効果を主張しない事、台帳の場所 | README の頭だけで引けた |
| 主張から根拠（20mm の計算と確かさの種類） | 地図と claims から届いた |
| 読んだファイル | 22 件（まとまった範囲 9、一部の行 13）。判断待ちを探す grep が多かった |

見つかった問題と直し:

| 問題 | 直し |
|---|---|
| 判断待ちの一覧が無く、散らばっている | `open.json` を足した。根拠の文も検査する |
| 地図の「20mm 足りない」から「初期の寸法で」が落ち、形の欠陥に読める | 一言を直した |
| README の「実装済み」と台帳の doing が食い違う。裏の制作の語も紛らわしい | 見出しと f19 の名前を直し、状態の定義を書いた |
| 輪の「人」が学ぶ人か作り手か分からない | 要約を「版の間に」と直した |
| f10 の名前と中身がずれる。f06・f18 に未確認の点が無い | 直した |
| README の手順の行末が `\\` で、行が続かない | 確かめて直した |

**この試験の弱さ**: 読み手は同じモデルで、外の AI の読み方ではない。1 回で、直した後の読み直しはしていない。`./run.sh` の結果の out/ は git に入らないので、clone しただけでは試験の結果を読めない点は残した。
