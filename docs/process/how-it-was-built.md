# この作品の作り方: 本人は窓口を通して決め、作る側のセッションには触れない

本人の決定で、作品だけでなく開発の方法も記録に入れる。

**この文書の確かさ**: 書き手は作る側のセッション（Claude Code）で、見えるのは届いた文面と自分の作業記録だけ。本人の手元と窓口の中は見えない。だから「本人の説明」と「作る側で確かめた事」を分けて書く。

## 進め方

| 役 | 誰 | している事 |
|---|---|---|
| 本人 | 人 | 決める。線を引く。作品の考えを言葉にする。できた物を見て評価する |
| 窓口 | 本人の個人エージェント（Claude のセッション） | 本人の言葉を作る側へ取り次ぎ、作る側が上げた判断を本人へ届ける |
| 作る側 | Claude Code のセッション | 調査、設計、実装、検査、記録。判断は推しを付けて窓口のキューへ上げる |
| 受け皿 | 本人の作業環境側の担当 | push の前の検査（ゲート）の管理、GitHub の repo の作成と最初の push |

### 本人の説明

開発期間中、本人は作る側のセッションに直接触れていない。指示と判断はすべて窓口を通し、判断は 1 件ずつ提示され、成果物は実物を見て評価し、中継が届いたか確かめる形で進めた。本人の入力は、判断・哲学・線引き・実物の評価だけ。

### 作る側で確かめた事

| 説明の点 | 作る側から見えた事 |
|---|---|
| 窓口を通した | 届いた文の多くに【本人決定】【本人の指摘】【窓口】などの見出しがある。「軸の形の比較と原図の入れ込みを進めて」のように見出しの無い短い文もあり、これは誰が打ったか文面からは分からない |
| 1 件ずつ提示 | 作る側が上げた形は 1 件ずつとは限らない（批判的レビューの決める点は 1 枚に 7 点＋1 点）。本人にどう見せたかは見えない |
| 実物を見て評価 | 11-02 の時点で、届いた評価は型紙 v5 の仮説 A の「よくなった」の 1 件。紙で組んで動かした記録は 0 件で、[試行の索引](trials/README.md)にも載せていなかった。その後 11-04 に成人 5 人で 1 回試し、試行の索引に載せた（記録 R-0001・R-0002） |
| 中継の確認 | 確かめる場面は作る側からは見えない |
| 入力の種類 | 判断、哲学、線引き、評価のほかに、作業の順の指示（「虎の雛形を進めて」）、機能の追加の決定（持ち寄りの場）、設計の入力（仮説を自分で立てる道）、問いの提示（批判的レビューの論点）も届いた |

### 説明に足して書いておく事

- **窓口の文は本人の言葉と同じではない。** 引用の後に、窓口の読み取りや手順の分解が続く文が多い。どこまでが本人の言葉かは、鉤括弧の引用より外は分からない。
- **最初の入力は事前の資料だった。** 開始の指示は、事前に用意した計画書とメモを読むよう指していた。扱いは [README](README.md) の「事前の検討との関係」に書いた。初期値の一部がそのメモ由来だった事は、点検で見つけて測定から出し直した（[research/06](research/06-rederive-defaults.md)）。
- **作る側だけで全部を作ったわけではない。** repo の作成、ゲートの管理、最初の push は受け皿がした。14:40 の決まり「製品 repo に触るのは作る側のセッションだけ」と、push を受け皿がした事の関係は整理していない。ゲートの判定語は 11-02 20:28〜20:29 に受け皿の側で変わり、FAIL 3 が FAIL 0 になった。作る側は変更の中身を読んでいない。
- **文書から消した行がある。** ゲートで止まった `CLAUDE.md` と `docs/process/README.md` の 1 行ずつを、本人の決定（20:20）で消した。作る側は消さずに本人へ判断を上げていた。消した行は git の履歴に残り、履歴は書き換えていない。
- **この文書の範囲は上の 4 役。** 本人の決定で、人のレビューは受けず、批評は Claude のセッションだけで行う（[J-018](decisions/J018-no-peer-review.md)）。これまでの事は、作る側から見えた範囲をそこに分けて書いた。

## 弱さ 1: 判断待ちで止まった時間

作る側の最後の出力から、次の文が届くまでの間隔を会話の記録から測った（11-02 14:00〜20:33 の 393 分のうち）。

| 届いた時刻 | 間隔 | 待っていた物 |
|---|---|---|
| 14:40 | 21 分 | 3 つの物差しの採点と案の比較の後 |
| 15:16 | 11 分 | 軸の形の比較へ進むかの答え |
| 16:43 | 24 分 | 手順の紙へ進むかの答え |
| 17:08 | 21 分 | 名前の比較の後（下の取り違え 1） |
| 17:43 | 22 分 | 輪の後半へ進むかの答え |
| **20:19** | **124 分** | 批判的レビューの決める点 |

10 分以上の間隔の合計は 223 分で、全体の半分を超える。別の決定の後の短い間隔はこの表に入れていない。

- 一番長い 124 分は、作る側が「答えが出るまで裏の制作と言葉の口は作らない」と決めて止まった結果でもある。答えに依存しない検査の補強や持ち寄りの再確認はできたので、待ちの全部が本人の側の原因ではない。
- 待った理由が「進めて」の一言で解ける場面が 4 回あった（15:16、16:43、17:13、17:43。17:13 は 5 分で上の表の外）。作る側が次の作業へ自分で進めば縮んだ時間で、確認を挟みすぎた可能性がある。
- 間隔は本人が考えていた時間とは限らない。窓口の中の滞在時間は測れない。
- 11-02 20:34 時点で、作る側が上げたカードのうち 10 枚が開いたまま残っている（書名と歌の読みの確認、実物の試作の依頼、API の鍵とモデルの承認など）。実物の試行が 0 件なのは、待ちと、作る側がソフトウェアを先に進めた事の両方による（11-02 の時点。実物の試行は 11-04 に 1 回した）。

## この方法で分かった事（作る側の見立て。測定ではない）

- **良い点**: 本人の入力が決める所と言葉に絞られ、作る側は推しと根拠を必ず添える事になった。判断の記録が自然に残る。
- **悪い点**: 問いが決定に見える形で届くと、作る側は作ってしまう。作る側も問い返さずに走った（取り違え 1、2）。待ちの間に手が止まる。
- **変えた事**: 決める点は推しを付けて 1 枚に集め、本人の言葉で片付く物はキューから外す（[J-013](decisions/J013-core-words.md)）。
- **まだ変えていない事**: 問いの形で届いた言葉を、実装の前に一度問い返す決まりは作っていない。次の取り違えを防げるかは未確認。
