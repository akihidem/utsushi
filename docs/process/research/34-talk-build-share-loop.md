# 34 話す・作る・残す の一周と、エンジンごと改善する輪（提出の核）

本人の言葉（2026-11-05 昼、窓口を通して届いた）:

> 今やってること。①インカメラか音声で AI が作った仮説を見ながら自分の考えを話す。②実際に作る。作りながら工夫などを話す。これをフィードバックとして型紙を改善するほか、型紙を生成するエンジンごと改善することができると面白いサービスになると思う。いまの実装でどこまでできる？

> ③できたものをアップロードして、工夫した点や考えなどをインカメラか音声で残す。ということをしてその内容をギャラリーで見れるし、システムも改善ループに入れる。としたい。

> 今話してるこの部分が今回のハッカソンの核になる！！

引用の外は書き手の整理で、本人の言葉ではない。表の状態は 11-05 午後の main のコードを読んで書いた。「ある」は main で試験が通っている物で、人が使った確認は別に要る。枝にしか無い物は「作りかけ」に書く。

## 一周の形

```
① 仮説を見ながら、自分の考えを話す
② 作りながら、工夫を話す
③ できた物を上げ、工夫と考えをカメラか音声で残す
        ↓
他の人の作った物のギャラリーで見られる  ＋  型紙の版が直る  ＋  エンジンごと直る
```

前提は本人の言葉のまま: 「型紙が正解ではなくて、とりあえずAIが考えた仮説であるということを明示する。システム側もそれを認識した上でループを回す」。

## 今の実装でどこまでできるか

| 段 | ある | 作りかけ | まだ無い |
|---|---|---|---|
| ① 仮説を見て話す | 予想を書くと仮説の札が並ぶ。自分の仮説を字で残せる | 開いたらすぐ札が並ぶ形（#266）。内カメラは鏡だけ（端末の中で映す。残さない）。話した考えを残す口（#279） | ― |
| ② 作りながら話す | 作りながら見る頁（手順を進める・止まった札）。声か字で聞くと手順だけ答え、聞いた言葉と止まった段が残る | 工夫を字で書く欄（#266）。作りながら工夫を話して残す口（#279）。作る過程の動画から札を付ける道（#225。本人の動画待ち） | ― |
| ③ 上げて残す | 手帖で写真と動画を上げる。撮影情報を落とす。感想の字。上げた写真と動画はギャラリーで見られる | 工夫の字と、他の人の作った物のギャラリー（#266）。動画の札に「人の工夫」の種類（#225）。上げた後に工夫と考えを話して残す口（#279） | カメラで工夫と考えを残す口 |
| 型紙の輪 | 記録 → 人の説明 → 人が寸法を 1 つ変えて次の版 → 次の人は直した版を刷る。鍵なしで回る | 工夫の字を輪の担当へ渡す（#266）。Claude の読みと案は、偽の応答の試験だけ。本物の API は 0 回（U-05） | 話した考えと工夫を、輪の材料にまとめる所 |
| エンジンごと | 雛形の床と版、全玩具を刷る試験（手で直す時の支え）。サイトの記録を束にして渡す口（omochae.engine_bundle、#278）。paper-to-toy の main に、束の入口・案・人の採否・版の台帳（omochae.engine_loop） | 話した字を束に足す所（#279 の後）。報告の形・検査・雛形と形ごとの集計（paper-to-toy の枝 engine/intake。main に未） | 報告の集計から直しの Issue の案を起こす所。直した雛形を全玩具で確かめて人が採る輪 |

話した物が流れ込む先の形（サイトの線が用意し、声の担当と合わせる）:

- 字になった考えと工夫は記録の欄に入れる。②の工夫は手順の番号を付けて、工作の様子にも残す。
- 字の床は今の記録と同じ（長さ・連絡先）。声そのものは残さない。

## 守る線との当たり（本人に決めてもらう点）

1. **カメラと声を残すか。** 今の決まりは「子どもの写真・声は扱わない」（spec の I2）で、動画は「顔や声が入った動画は、映像を頁に出さず、札の字だけで回してよい」（11-05 の本人の決定）。内カメラは顔が映る。推し: 声は端末で字にして、字だけを残す。写真は作った物だけで、顔の映った映像はギャラリーに出さない。
2. **公開の場のギャラリー。** 今の #266 のギャラリーは、合言葉なしの場で人の書いた文と写真を出さない（文の中の名前は機械で落とせない。J-028）。ほかの頁（玩具の頁・手帖・図鑑）には、人の書いた説明や自分の仮説の文が出る所が残っている（別の目の点検で確かめた）。本人の言葉は「ギャラリーで見れる」。推し: 人が確かめた物だけを公開の場に出す口を足す。持ち寄りの確認と同じ形にする。
3. **子どもが使う時。** 上の 2 つは成人の前提で書いた。子どもの場は同意の形を決めてから（research/31 の 4）。

## 順番（本人の決定、11-05）

厚くする順は本人が決めた。

1. 作りながら話した工夫を、その場で記録に入れる（#279）。
2. サイトの記録を、エンジンの報告の形に渡す口（#278）。
3. 報告の集計から、エンジンの直しの Issue の案を起こす。直すかは人が決める（paper-to-toy #63 の続き）。

土台の #266（開いたらすぐ作る・ギャラリー・工夫の欄）は、1 の頁が同じ所を使うので先に入れる（書き手の整理）。

同じ決定で足した事: 職人や玩具店、実際に遊んだ人の情報も、同じ入口（ギャラリー・持ち寄り）で集める（#285）。

## 確かめていない事

- 人がこの一周を通した事。声の認識が工作の場の音で使えるか。
- 工夫の字で本当に型紙やエンジンが良くなるか。学習の効果と同じく、主張しない。
