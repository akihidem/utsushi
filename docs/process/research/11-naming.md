# 11 名前の候補を比べる

**事前メモとの関係**: うつしかがみの名と、下の考えは本人の事前の下書きにある。照らし合わせはここで行った。

## 訂正: 「かがみ」は仕組みではなく哲学の話

最初の版は「鏡が部品や画面に実在するか」を調べ、「仕組みに無いので弱い」と結論した。**これは論点を取り違えていた。** 本人の訂正の通り、「かがみ」は次の考えを指す。

> AI は鏡。江戸の絵を映すことはできるが、映すだけでは遊べない。

この前提で読むと、今の作品の設計はこの考えと合っている。

| 考え | 今の設計 |
|---|---|
| AI は映せる | AI や作者の案は、絵と歌から読み取った仮説として出す |
| 映すだけでは遊べない | 仮説は答えではなく、人が作って試さないと決着しない。作る場面に AI は居ない |
| 映すより先に人がある | 予想か自分の仮説を先に書く（J-002・J-008） |
| 複数を並べる（J-002）、図を描き直す（J-007） | 「映しは本物ではない」という距離の取り方と矛盾しない |

取り下げた読み:「1 つの像を映す鏡と、複数の仮説は動きが逆」「比喩として弱い」は、比喩を部品の仕様のように読んだ物だった。

名前の決定は本人が窓口で行う。下は比べる材料で、推しは置かない。

## 作品の中心（名前が言い当てるべき物）

絵と歌だけが残る玩具の仕組みを、予想し、仮説を並べ、紙で試し、記録と人の知見で読み解いていく事。出口は紙で、画像解析や教育のチャットには見せない。

## 候補

GitHub の同名の repo の数は、名前での検索の結果（`utsushi` は部分一致を含む）。「写し」が工芸で名品を手本に作る事を指すという説明は一般的な知識で、調べた検索では定義を確かめられず、「仁清写」のような表記の例だけを確かめた。

| 候補 | 何が伝わる | 何が伝わらない | テーマ名との関係 | 同名 |
|---|---|---|---|---|
| `utsushikagami` | 作品名そのまま。「AI は鏡、映すだけでは遊べない」という哲学を持つ。音がきれい | 説明なしには、何をする物か | 同じ | 0 |
| `toy-kagami` | 玩具の物である事。鏡の語は残る | 「映す」が抜けて哲学が半分になる。試す事、江戸 | 半分残す | 自分の空の repo のみ |
| `utsushi` | 写し・映し。古い物に倣って作る工芸の語に通じる。短い | 鏡の語が抜ける。仮説と試行。忠実な写しに聞こえ、「復元ではない」と少し衝突 | 前半を残す | 48 |
| `karakuri-yomi` | からくりを読み解く事。「読み」は予想の意味も持ち、予想を先に書く設計に合う。人の知見を寄せる事も含められる | 紙で作る事 | 無関係。作品名を残すなら副題の関係になる | 0 |
| `tameshigami` | 試し紙。1 枚の紙で試す出口。画像解析に見えない | 江戸の玩具、持ち寄り | 無関係 | 0 |
| `omochae` | おもちゃ絵。今のコードの名前 | 試す事。絵の展示や画集にも読める | 無関係 | 0 |

## 見立て

最初の版は鏡を問題視して `karakuri-yomi` を推したが、前提が違っていたので取り下げた。残る違いは、repo 名に作品の哲学を持たせるか（`utsushikagami`）、何をする物かを持たせるか（`karakuri-yomi`・`tameshigami`）。後者を選ぶ時も、作品名としてうつしかがみを残せる。
