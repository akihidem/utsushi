# 09 持ち寄りの場の設計

本人の決定で範囲に入った。職人・店・有識者・思い出を持つ人が、現存する玩具の情報や写真を寄せ、書き足されて育つ場所。

**事前メモとの関係**: 案そのものは本人がキックオフで出した。事前メモには「週内に入れるなら記録の欄を増やす形か」という見立てがあるだけで、下の設計はここで考えた。

## 何を受け付けるか

| 種類 | 例 | 要る欄 |
|---|---|---|
| photo 写真 | 手元の古い御来迎の写真 | 権利の根拠は必須。根拠が不明なら公開しない |
| info 情報 | どこの店が作っていたか | 出所 |
| memory 思い出 | 子どもの頃、筒を下げて遊んだ | いつ頃・どこで（おおよそ） |
| knowhow 作り方の知見 | 職人の紙の扱い | 確かさの種類 |

どの投稿にも「確かさの種類」を付ける（見た・持っている・聞いた・覚えている・作っている・推測）。思い出を事実に格上げしない。図の文の印と同じ考え方。

## 受け口の比較

| 案 | 外の人が使える | 公開前の確認 | 他人の個人情報 | 週内の量 | 判断 |
|---|---|---|---|---|---|
| A この repo の手元の画面 | 運営者の機械だけ | できる | 手元に留まる | 小 | **作る** |
| B GitHub の Issue | 使えるが、アカウントが要り職人に遠い | できない（投稿と同時に公開） | 公開に残る | 小 | 捨てた |
| C 既製のフォームのサービス | 使える | できる | 外部の事業者に渡る | 小 | **本人が採った（11-03、[J-021](../decisions/J021-contributions-form-students.md)）** |
| D 自前の公開サーバ | 使える | できる | 自分で守る責任 | 大。認証・荒らし・保管・削除の運用が要る | 週内は作らない |

**決めた事**: A を作り、受付から公開までの決まりと検査を本物にする。外の人に開く入口（C か、提出の後の D）は、答えを本人に聞く。形式を 1 つに決めてあるので、入口を足しても確認と検査はそのまま使える。

## 貯まり方

```
投稿 → 受付箱（git に入れない）→ 人が確認 → 公開の記録（data/contributions/）→ 公開の頁・Claude の道具
                                 └ 却下        └ 取り下げで公開から外す
```

- 連絡先は別のファイルで受付箱に置き、公開の記録に決して入れない。
- 他人の写真も文も、本人の答えが出るまで repo に入れない（公開の記録も git の外）。提出物は公開で、主催に永続のライセンスを与える規約があり、「この場所での表示だけ」を選んだ人の同意の範囲を超えるため。
- 写真は受付で描き直し、位置情報などの付帯情報を落とす。
- 取り下げは番号だけの記録を残し、公開の記録が別の経路で戻っても出さない。
- 却下は写真・連絡先・本文を消し、番号と確認の記録だけを残す。
- 連絡先の形が本文にあれば、受付の時に投稿者へ知らせる。連絡先なら本人が直し、誤検知なら確かめて送る。その投稿には印が付き、確認者が全文を読んで判断する。確認者は他人の言葉を書き換えない。
- 最初は受付で断っていたが、寸法や日付の並びなど普通の文が送れなくなると検品で分かり、断り切らない形に変えた。
- ID は C-0001 の連番で、取り下げても番号を使い回さない。

## 投稿の扱いの線（検査 F10）

| 検査 | 見る事 |
|---|---|
| F10.intake | 種類・本文・確かさの種類が決まりの中。同意の 3 点（規約、18 歳以上か保護者の同意、写真に人が写らず文に他の人の連絡先や私的な事が無い）が全部ある。画像は実際に読める JPEG か PNG で 5MB まで |
| F10.rights | 写真は権利の根拠と持ち主が要る。根拠が不明の物は公開にできない |
| F10.review | 公開には人の確認の記録（誰が・いつ）が要る。CLI は端末で人が番号を打たないと公開しない（AI や自動の処理を止める補助で、完全な保証ではない）。状態の移り方は受付→公開か却下、取り下げはいつでも |
| F10.pii | 公開する文と権利の持ち主の欄にメールアドレス・電話番号・郵便番号の形があれば公開できない。全角や見えない文字はそろえてから見る。補助なので、確認者は `show` で全項目を見る |
| F10.public | 公開の頁と道具は、確認済みで取り下げのない物だけを返す |
| F8（拡張） | 仮説が引く C-nnnn は公開済みの物だけ |

## コアの輪とのつながり

1. **投稿 → 仮説**: 公開済みで CC BY を選んだ投稿を、道具 `list_contributions` で前例として引く（「表示だけ」の文は外部の API に送らない）。「筒を下げた」という思い出は「下げる」仮説の根拠になるが、確かさの種類が付いたまま渡す。
2. **試行 → 問い → 投稿（鋭くする案）**: 仮説の間で実物では決着しない点を、知っている人への問いとして見せる（例:「筒は押しましたか、下げましたか」）。投稿が答えになる。これで作った人だけの輪が、作り手につながる。
3. **投稿 → 次の型紙**: 根拠に使うと、寸法や順位の変更の記録に C-nnnn が残る（F4）。変更を採るのは人。

問いの自動生成は仮説生成ができてから足す。今は玩具ごとの問いを人が書く。

## 3 つの物差しでの見立て（測定ではない）

| | 投稿の場なし（案 B） | あり |
|---|---|---|
| 完成度 | 3 | 2.5〜3（画面と検査が増える。外の人の入口は未定） |
| 鋭さ | 3.5〜4 | 4（作って分からない事を人に問う） |
| インパクト | 2.5〜3 | 3.5（職人と店が関われる入口。ただし週内に実際の投稿が集まるかは未知） |

**正直な弱点**: 週内に外の投稿が 0 件なら、見せられるのは仕組みだけ。実在の投稿が 1 件でもあると見え方が大きく変わる。架空の投稿を実在のように見せない。

## 作らない物（週内）

公開サーバ、ログイン、投稿どうしの書き足しの画面、自動の不適切判定、写真からの判定。「書き足されて育つ」は、同じ玩具の投稿が並ぶ形で最小に表す。
