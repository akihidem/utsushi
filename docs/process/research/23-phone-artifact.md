## 「アーティファクト」で何ができるか（作る側が Claude Code の Artifact の資料で確かめた事）

claude.ai に置くページで、iPhone の Claude のアプリやブラウザで開ける。ページに次の力を持たせられる。

| 力 | 中身 | この口での使い道 |
|---|---|---|
| sample | ページから Claude に聞く。見ている人の Claude で答えるので、utsushi の API の鍵は要らない | 手順の質問 |
| assets | 画像などを上げて置く。上げた物は Claude の側に置かれる | できた物の写真 |
| db | 共有の記録を置く。人ごとの私的な置き場もある | 上げた写真に添える短い記録 |
| user | 誰が見ているか（名前ではなく ID） | 誰が上げたかを ID で持つ |

制約: 見る人は claude.ai に入っている必要がある（招いた人か、同じ組織の人）。ページは手元の画面（127.0.0.1）にはつながらないので、手順と凡例はページに埋めて置く。

## 案

**推し: 「工作の手帖」アーティファクトを 1 つ作る（成人だけ、本人が招いた人だけ）**

1. 開くと玩具と仮説の紙を選ぶ（刷った紙の題と同じ名前。仮説の動き方は出さない）
2. 「困ったら聞く」: 手元の版と同じ線で答える。よくある言葉（谷折り・山折り・糊代・蛇腹・色の境・物差し）は埋めた説明から答え、ほかは sample で、その紙の組み方と凡例だけを渡して聞く。仕組み・どの仮説かの質問は答えない
3. 「できた物を上げる」: 写真 1〜3 枚と短い一言（何が起きたか。動いた・動かない・わからない）。上げた物は本人だけが見られる場所に置く（上げた人と本人だけ）
4. 持ち寄りとのつなぎ: 上げた物を、本人が見て選び、今の持ち寄りの床（同意・権利・確認・個人情報、F10）に通してから持ち寄りの場へ移す。アーティファクトから直接公開しない。repo にも直接は入れない（試行の記録として載せる時は本人が決める）

## 守る線（どの案でも）

- 予想が先（F9.prediction）。アーティファクトでも仮説の動き方は出さない
- 順位を付けない（J-025）。上げた物に点や票を付けない
- 子どもの写真・声は扱わない（今週は成人のみ）。顔が写った写真は本人が持ち寄りへ移す前に外す
- 答えは手順だけ。答えに仮説の名前や動き方が混ざったら出さない（手元の版と同じ出口の検査）

## 本人の設計の指定（2026-11-04 昼）と、作った形

本人: 「生徒向けの画面は机に置いて声で操作する。両手は工作で塞がってる。写真や動画をアップロードできるように。」

- **入れた物**（https://claude.ai/artifact/Ke2AuGJMHr5mpdxZp57KG3 の版 2）:
  - 答えを声で読む（端末の読み上げ。使えない画面では字だけ）。既定は入
  - 話し終えたら自動で聞く: キーボードのマイク（iPhone の音声入力）で話すと字が入り、2 秒止まったら送る。送るボタンを押さずに済む
  - 写真に加えて動画を上げられる（1 つ 20MB まで、3 つまで。動く所を 5〜30 秒ほど）。上げた動画は帖面で再生できる。「動画に声は入っていません」の確かめを足した（J-022 の声なしの決まり）
  - 机に置いて読めるよう、字と押す所を大きくした
- **入れられなかった物**: 手を使わずに声だけで操作する形（話しかけるだけで聞き始める）。アーティファクトの頁は、マイク・カメラなど端末の機能を直接使えない（claude.ai の頁の決まり。この利用者の頁の力の一覧にも無い）。今の形でも、話し始める前にキーボードのマイクを 1 回押す操作が残る。どうするかは本人に聞いている（一覧の U-36）

## 本人の指摘「文字情報が多い」（2026-11-04 昼）と、版 3

- 直した所: 読ませる説明文をほぼ外した。玩具は原図の小さな絵、紙は仮説の字だけの大きな印（A・C・D）、見た事は大きな印（矢印＝動いた、横棒＝動かない、問い＝わからない、波＝揺れた）で選ぶ。聞く・上げるは見出しを絵（マイクとカメラ）にし、読み上げと自動で聞くは丸い印の切り替えにした。凡例は線の見本の絵にし、組み方は畳んだ所の中に入れた。確かめの文は「大人の手元だけ・顔なし・声なし」の 1 行にした
- 残した字: 答え（声でも読む）、玩具の名、紙の字、組み方（開いた時だけ）、所蔵の 1 行
- 見た事の印は、成否や上下に見えない形にした（成功・失敗の言葉を使わない線、順位を付けない線）

## 本人の方向転換: 手帖を入口のサイトと地続きにする（2026-11-04 午後）

本人: 「最初のサイトと、いまアーティファクトで作った手帖は地続きの方が良いのでは。アーティファクトで作ってと言ったのが良くなかったね」。

- 作った物（凍結の前の範囲、外に出ない部分）: 玩具の頁から開く手帖の頁（画面の道 /toy/<玩具>/techo、`src/web/techo_site.py`）。入口 → 玩具の頁 → 手帖 → 試した記録が同じサーバの頁で一続きになる。見た目は A′ の白い展示に合わせ、字は最小
  - 聞く: 手元の版の手順の質問の口（src/api/ask.py）をそのまま使う。ブラウザの音声認識で、マイクを 1 回押すと話し続けられ（続けて聞く）、もう 1 回押すと止まる。答えは読み上げる。音声認識の無い画面では字の操作だけ
  - 上げる: 見た事を選ぶとその場で試した記録（R-番号）ができ、写真と動画（JPEG・PNG・MP4・MOV、1 つ 20MB、1 記録 3 つまで）がその記録に添う。置き場は git の外（data/records/media）。写真の撮影情報（APP1）は保存の時に外す
  - 試験: `tests/test_techo_site.py`（予想の前は開かない、仮説の名前と動き方を出さない、仕組みは答えない、刷っていない紙は断る、撮影情報を外す、型と出所と記録の有無を見る）
- 本人が決める物: iPhone から開くために手元のサーバを家の中の網に開くか（外に出る操作）、アーティファクトの手帖を消すか（戻せない）。カード 20261104-142933
- 提出の後: 公開のサーバ、持ち寄りの場へ移す口、話しかけるだけで始まる形

## 家の網に開く切り替え（本人の決定、11-04 午後）

本人が「家内網開放 = 開く（iPhone から手帖を使えるようにする）」と決めた。サーバを `--lan` を付けて起動すると、この機械の網の中の番地（私的な番地と .local の名前）だけを足して受ける。外の名前は今までどおり断る（DNS rebinding の守り）。書き込みは同じ出所の頁からだけ受ける守りもそのまま。既定（付けない時）は手元だけ。試験は `tests/test_lan_switch.py`。

- 分かっている限り: iPhone の Safari は https でない頁では音声認識を使えない見込み。家の網の http では、字の入力と読み上げ、写真と動画の上げ下げは使える。手を使わない声の操作は提出の後（https にする時）
