## 案の芯

今の順路は「原図 → 予想 → 仮説と型紙 → 作る」です。型紙は、作る側の読み（仮説）を寸法にした物です。型紙を先に渡すと、作る人の試行は、作る側の読みの中に入ってしまいます。

型紙を渡さずに絵だけから作ってもらうと、次の物が見えます。
- 人が絵のどこを動く所と読んだか
- 何から試したか
- どこで止まったか

これは、作る側の読み（仮説）とは別の所から来る、仕組みの手がかりです。哲学の「失われた玩具の動きを、紙で実験して確かめる」の、実験する人を作る側から作る人に移す形になります（[philosophy](../philosophy.md)）。

## Claude は何を得られるか（得られない事も）

得られる事（その場の会話の中で）:
- コマか短い動画から、見えた事を書ける。
  - どの部品を先に作ったか
  - どこを何度も折り直したか
  - どの向きに動かそうとしたか
  - 手が止まった時間
  - 今の観察の補助と同じ線で書く（見えた事と、見えなかった事）
- 何人分もの観察を並べて、似た所を拾える。
  - 同じ所で止まる
  - 同じ勘違いをする（例: 扇の要を固定したまま押し上げようとする）
  - 同じ順で試す

得られない事:
- Claude の重みは、この観察では変わりません。会話が終わると、Claude は見た事を覚えていません。
- 「得る」は、観察を記録として台帳に積む事です。積んだ記録を次の会話の Claude と人が読み、次の仮説と型紙の直しの根拠にします。
  - 知見が溜まるのは repo の記録の側で、Claude の中ではありません。
  - Physical AI のデータ取りの子ども工作版（U-45）の、データの層がこれに当たります。
- 動画から仕組みの正解は決まりません。
  - 何人も同じ形に行き着くのは、「絵がそう読める」事の手がかりで、昔の玩具の作り方の証拠ではありません。
  - 観察と推測を分けて書きます（仮説の記録の evidence と同じ線）。

再生の知見として残す形（案）:

| 欄 | 中身 |
|---|---|
| 止まった所 | 何分目に、どの部品で、何秒止まったか |
| 試した順 | 作った部品の順と、作り直した回数 |
| 動かそうとした向き | 押す・引く・回す・振る、と、どこを持ったか |
| 勘違いの形 | 絵のどこを、どう読み違えたと見えるか（推測と書く） |
| 仮説との関係 | 今の仮説のどれに近い作り方か、どれにも当たらないか（当たらない物は新しい仮説の候補） |

## 端末の置き方と写し方

本人の具体化（2026-11-05）: 「生徒の一人一台端末や iPhone を机の端に置いて、端末のカメラで生徒の上半身を写す形に。間に手と動画と紙があり、作成の様子を見れるようにする」。

- **置き方:** 端末は、机の向こう側の端に立てる。作る人と端末の間に、手・紙・作りかけの玩具が入る。
- **写し方:** 内カメラ（画面の側のカメラ）で写す。
  - 画面には、作る人に向けて次の物を出す。
    - 手本（原図、型紙を比べる段では型紙）
    - 止まった時の返事
  - U-44 の「原図が自分と画面の間にあるように映る」と、同じ置き方で両立する。
- **写る物:** 上半身と机の上（手・紙）。止まった所・試した順・動かそうとした向きは、手と紙から読める。体の向きと手の止まりからは、止まった時間が読める。
- **顔の扱い:** 上半身を写すと顔が入ります。人を見分けられる映像になるので、決まりの 1（下）が強くなります。案は 2 つです。
  - (a) 端末を少し下に向け、肩から下と机の上だけを写す。観察に要るのは手と紙です。
  - (b) 上半身を写すが、コマを送る前に機器の中で顔の所をぼかす。
  - 推し: (a)。仕組みが軽く、写らない物は漏れない。
- **端末の役:** 学校の一人一台端末（iPad・Chromebook）でも、iPhone でも、ブラウザの頁で動く形にする（今の https のデモのリンクと同じ）。
  - 立てる台は、紙で作れる物を型紙に入れてもよい（案）。

## 今の決まりとぶつかる所

1. **子どもの映像と声:** 今週は扱わない決まりです（成人のみ）。
   - カメラで子どもの作る様子を見て Claude に渡すのは、子どもの映像を外の口へ送る事になります。
   - 機器の中で映すだけの U-44 の形と違い、観察には映像を API に渡す必要があります。
   - 保護者の同意の形と、映像を残さない仕組み（コマは送った後に消す・字の観察だけを残す）を本人が決めるまで、子どもでは動かせません。
2. **その場の返事と J-013（人の説明とアイディアが先）:**
   - 試行の途中で Claude が返事をすると、作る人のトライアンドエラーを奪うおそれがあります。
   - 推し: 返事は、聞かれた時と、長く止まった時だけにする。
     - 返事の中身は、次に試せる事の問いかけまで。
     - 仕組みの答え・正解の形は言わない（今の聞く口の is_mechanism の線）。
3. **J-025（順位を持たない）:** 何人もの観察を並べても、早く作れた人を上にしない。集計は止まった所と試した順の数だけにする。
4. **費用と遅れ:**
   - 1 人 30 分を 10 秒ごとに 1 コマで見ると、180 コマです。
   - その場の返事には、数秒の遅れが出ます。
   - 今の予算の見張り（`src/api/budget.py`）の中で、コマの間を決めます。

## 今の設計への反映（案）

- 順路に「型紙なしで作る」の道を足す。順は「原図 → 予想 → 型紙なしで作る（観察）→ 型紙と比べる」です。型紙は、作った後に比べる物として出します（予想の後にだけ仮説を出す F9 と同じ向き）。
- 型紙なしで作った観察を、仮説の記録の evidence の種類に足す。
  - 例: 種類は「作る人の試行の観察」。
  - 観察と推測を分ける線は、今のまま守る。
- U-44（内カメラで選ぶ）と U-45（作る様子の蓄積）の器を、そのまま使う。
  - 止まった所・試した順は、U-45 の出来事の記録と同じ欄にする。
