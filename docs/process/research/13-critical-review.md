# 13 前提への批判的レビュー

本人の依頼で、J-012 の前提を別のセッション（同じアカウントの Claude）に批判させた。前提を書いた者に結論を渡さず、資料と本人の問いだけを渡した。

**読むときの注意**:

- 批評役も Claude で、人の専門家の査読ではない。
- 文献の数値は批評役が読んだ範囲の物で、この文書の書き手は読み直していない。全文を読めていない文献も多い（下の表）。
- 実物の試行は 0 件、本物の API も未実行なので、この作品への当てはめは全部推論。

**事前メモとの関係**: 「答えまで固めない」方向の考えは事前の批評のメモにもあった。下の判定は、そのメモを渡さずに行った。

## 前提ごとの判定

| 前提 | 判定 | 直す向き |
|---|---|---|
| 1. 本体は裏で Claude が作り、検証する | 条件つき | 固めるのは答えでなく試す条件。Claude は紙が開くかを確かめられない |
| 2. その場の生成は目玉にしない | 賛成 | 理由を「もう古い」から、考える所を奪う危険と、確かめる時間が取れない事に替える |
| 3. 自分の仮説の口だけがその場で動く | 今の形では反対 | 解釈と提案も使う時に呼ぶので「だけ」が成り立たない。子どもの自由文が API に届く唯一の口になる |

## 一番大事な 2 点

1. **問いが 2 種類混ざっている。** 「昔の職人がどう作ったか」は開いた問いだが、「振り子の周期」には物理の答えがある。
2. **輪に「試した後に学ぶ」段が無い。** 答えを固めない方針を物理にまで広げると、手引きのない発見学習になり、そちらは証拠が不利。

## 問い 1: しっかりしたコンテンツは必要か。固めるのは答えか条件か

| | 主な根拠 |
|---|---|
| 必要 | 手引きのない発見学習は明示的な指導より劣り（Alfieri 2011: d=-0.38）、手引きつきの発見は有利（d=0.30）。小 3 の浮き沈みで手厚い支援の群が 1 年後も優れた（Hardy 2006）。組めない型紙の失敗は物理の失敗でなく工作の失敗【推論】 |
| 答えまで固めると弱まる | 4〜6 歳で教えられると探索が狭まる（Bonawitz 2011）。問題解決を先にすると有利（Sinha & Kapur 2021。数値は検索要約のみ）。予想してから見ると理解が深まる（Crouch 2004） |

**判定**: 「必要」は半分本当。固める対象を 3 つに分ける。

| 対象 | 試す前 | 試した後 |
|---|---|---|
| 組める・測れる・安全・図の根拠の種類 | 固める | 記録で直す |
| 物理の原理（答えのある問い） | 見せない | 説明を開く（今は無い） |
| 歴史の仕組み（開いた問い） | 固めない | 固めない。根拠の種類だけ示す |

子どもへの証拠は一番薄い。「年齢を限らず」を学習の主張にしない。

## 問い 2: AI の役目はリアルタイムか、版の間の調整か

- **リアルタイムの論**: AI チューターが能動学習を上回った（Kestin 2025。Harvard の学部生で、専門家の解答を prompt に入れている）。これは作り込みの必要を示す材料でもある。
- **版の間の論**: 素の GPT で練習は 48% 上がり試験は 17% 下がった（Bastani、作業論文の数値）。教材を試行で直す方法には design-based research や lesson study の蓄積がある。
- **版の間の論への反論**: その蓄積は人が直した研究で、**AI の版の調整が学習を上げた直接の証拠は見つからなかった**（検索は少ない）。版を直すと「動いた」は増えるが、学習の向上とは限らず、見分けるのに要る難しさまで削る恐れがある【推論】。

**判定**: 二択なら版の間。ただし相手は子どもでなく教員と作者。Claude が直してよいのは組みやすさと測りやすさまで。これは効果の主張でなく設計上の賭け。

## 問い 3: リアルタイムの危険

- **危険**: 頼り切りの結果（Bastani）。生徒は自分の学びを正しく評価できなかったので、**満足度の聞き取りはこの作品の証拠にならない**。紙は評価を挟まずに開く・開かないで応える。AI の評価はそれと競合する【推論】。
- **言いすぎだという論**: 家庭には先生がいない。行き詰まった子はやめる。正しい方略を知らない子には正誤の即時フィードバックが効いた（Fyfe & Rittle-Johnson 2015）。
- **判定**: 「即時か遅延か」を論拠にしない（研究が割れる）。線引きは、**正誤・原因・解釈・次の手を子どもにリアルタイムで返さない**。行き詰まりには AI を使わない足場（固定の問いの札、部品ごとの確かめ方、型紙なしで作って記録する道）を置く。

## 書き手の見解

判定におおむね賛成する。とくに次の 3 つは、前提を書いた時に見落としていた。

- 物理と歴史の問いを分けていなかった。
- `loop.py` の解釈は、人が考える前に Claude が原因と確信度を出す。予想・観察・説明の「説明」を AI が取っている。
- 確かさの段を 1 本にすると、登るほど「正しい」と読める。「実物で試した」は「昔こうだった」を意味しない。

一方で、版の間の調整は証拠のない賭けのままで、週内に学習効果は検証できない。実物の試行が 0 件のうちは、どの方針も言葉だけである事は変わらない。

## 今の設計で問題になる箇所

| 箇所 | 問題 | 直す向き |
|---|---|---|
| J-012 の確かさの段 | 1 本で、登ると正しさに近づくように読める。Claude の段が権威だけを足す | 「組めるか」と「歴史の根拠の種類」に分け、「どこまで試したか」と呼ぶ |
| `loop.py` の順位、`hypotheses.py` の一覧 | 全体の順位と集計が次の人に見え、記録から作られた答えになる。記録 1 件でも順位を変えられる | 学ぶ人の画面から順位を外す |
| `loop.py`・`loop_agents.py` の解釈 | 人の説明より先に Claude の原因が出る | 人の説明を先に必須にする |
| `instructions.py` と `records.py` | 紙の 3 つの問いを入れる欄が記録に無い | 欄を足す |
| `records.py` の集計 | 版を混ぜて数えるので、版の比較ができない | 版と開く力で分ける |
| `hypotheses.py` の予想の確かめ | 誰かが予想を書くと、共用機の全員に一覧が開く | 班か回で区切る |
| 輪の全体 | 試した後の説明の段が無い | 物理の問いだけ、記録の後に説明を開く |
| `research/04` の Q5・Q7・Q8 | 端末・鍵・刃物があり、今の道具は子どもが使えない | 子どもの担当は紙だけと明記する |

## 同意と個人情報

試行の記録には同意も年齢の扱いも無く、`check_pii` は「3 年 2 組のたろう」を通す。記録の全文は API に送られる。子どもの記録を集める前に、保護者の同意、学校の決まり、API の未成年の指針、公開の repo に入れない事が要る。法の適用は確かめていない。

**すぐ直した事**: `data/records` と `data/loop` を git の外に置いた（実データはまだ 0 件）。公開の repo に個人の記録が黙って入る道を、答えが出る前に閉じるため。
