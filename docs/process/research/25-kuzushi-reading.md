本人の決定（2026-11-04、窓口を通して届いた）: 「くずし字 f14 = 入れる」。[research/17](17-field-and-continuers.md) の問い 6 で決めた「今週は書くだけで作らない」を、本人が変えた。

作った物: `src/web/kuzushi.py`、手元の画面の道 `GET /zukan/<出典 ID>/yomi` と `POST /zukan/<出典 ID>/yomi`（`src/web/play_server.py`）、図鑑の玩具の段からのリンク「くずし字を読む」（`src/web/zukan.py`）。試験は `tests/test_kuzushi.py`。

## 流れ

玩具と同じく、予想が先（F9.prediction、[philosophy](../philosophy.md)）。

1. 書く前の頁: 絵の歌の所を大きく見せ、自分の読みを書く欄を置く。人が確かめた読みはまだ出さない
2. 書いて送ると、同じ頁の応答で、書いた読みと人が確かめた読みを横に並べる。違って読めた字に線を付け、「ここが違って読めた所」と書く。点・○×・合否の言葉は出さない（[J-025](../decisions/J025-no-ranking.md)）
3. その下に、読みが割れた事と、本人がどう決めたか（[research/16](16-scan-titles.md)）を観察の文で出す。活字の読み（`printed_text`、御来迎の「怠らじ」）もここに、作る側が読んだ文として出す

書いた読みは保存しない。応答の頁に映すだけで、記録の置き場（`OMOCHAE_DATA`）にもログにも書かない。試験は、送った後に記録の置き場が空のままかで見る。

## 採らなかった読みを出すか

頼みの中では「採らなかった読み」と印を付けて出してもよい、とされていた。ただし既にある線と食い違うなら出さない、とも。

- [J-016](../decisions/J016-zukan-labels.md) の追記（11-04）: 「怠らし」は出ない
- `tests/test_zukan.py`、`tests/test_play_server.py`: 頁に「怠らし」が出ない事を見ている
- `src/api/generate.py` と `tests/test_transcription_filter.py`: 採らなかった語を API にも渡さない

**出さない事にした。** 割れた事は「手元の複写 A と B で一部の読みが割れた」「本人が何日に複写 B（頁 78）の読みに決めた」「もう一方は記録に残すが、この頁には出さない」の形で書き、採らなかった字の並びは書かない。出典の `checked_scope` は割れた二つの語をそのまま書いているので、画面には出さない。

## 印の当て方（F6.label）

頁の文は `<li>` にし、どれも図鑑と同じ 3 つの印のどれかを付け、`labels.check` を通してから描く。

| 文 | 印 | 理由 |
|---|---|---|
| 人が確かめた読み | 原文の引用 | `zukan.quote_lines` と同じ物（`checked_by` があり、採らなかった読みでない） |
| 書いた人の読み | 観察 | その人が絵から読んだ事。試していない考え（仮説）とは違う、と書き手が判断した。**本人に確かめていない** |
| 割れた事・決めた事 | 観察 | 出典の記録に残した事実 |
| 活字の読み | 観察 | 作る側が複写から読んだ文。本人が確かめたのは割れた語と表記で、活字の文を 1 字ずつ確かめたのではないため、原文の引用にしない |

## 歌の所の枠

`out/sources/<出典 ID>.jpg`（NDL の IIIF の頁の切り出し、1600×2656）に対する %。画像は新しく作らず、`/picture/<出典 ID>` の 1 枚を CSS で切る（枠の箱の縦横比を枠に合わせ、`img` の幅と位置を枠に対する % で置く）。

| 出典 | 玩具 | x | y | 幅 | 高さ |
|---|---|---|---|---|---|
| NDL-1187053-R0000005-L | 御来迎 | 15 | 25 | 77 | 27 |
| NDL-1187053-R0000014-R | 張子の首振り虎 | 10 | 29 | 70 | 34 |

決め方: 作る側（Claude Code のセッション）が画像を見て、歌の行の右端（最初の行のふりがな）から左端の行まで、上はふりがなの頭から下は最後の字までが入る所を選んだ。表示の縮尺で座標を読み、% に直して丸めた。その % で PIL で切り出した画像を見て、どの行も字が切れていない事を確かめた（御来迎は下に扇の頭が、虎は下に犬の頭が少し入る。字を切らない側に寄せた）。ブラウザの画面（Chrome headless）でも、御来迎の枠が同じ所を出す事を見た。

同じ所を NDL の高い解像度で開くリンクも置いた。見開きに対する % に直して（左の頁は x/2、右の頁は 50 + x/2）`api.tools.zoom_url` に渡す。頁の外へはみ出さない検査は zoom_url の物をそのまま使う。

## 比べ方

`difflib.SequenceMatcher` で字ごとに比べ、違った所に線を付ける。空白は比べない（行の切れ目やふりがなの書き方の違いを数えないため）。違った所の数や割合は出さない。

分かっている限り:

- **字で比べるので、読み（音）が同じでも字が違えば線が付く。** 「おかむ」と「拝む」、「なむ」と「南無」は違って読めた所として出る。くずし字の読みでは、仮名で書くか漢字で書くかは読めたかどうかと別の事だが、今は分けていない
- 濁点の有無（「し」と「じ」）も 1 字の違いとして出る
- 確かめた読みも、割れた中から本人が決めた物。並べるだけで、どちらの字が元の本に近いかは言わない
