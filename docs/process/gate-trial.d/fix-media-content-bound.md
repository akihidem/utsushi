## 安全の事項 2 への対応: 確かめた写真を、同時の上げや後からの書き込みで差し替えさせない（Issue 対応の担当、fix/media-content-bound、11-08）

- 目的: 人が「物だけ」と確かめた写真と動画だけが公開に出る、という守りを、同時の上げの下でも崩さない
- なぜか: 安全の事項 2（本人の指示 11-08・本人の条件「サイトの機能は維持した状態で、見た目、挙動は変えずに、セキュリティの事項にだけ対応する」）。保存（techo_site.save_media）は変換の前に数えた番号の名（m<数+1>）へそのまま書き、確認（media_review）は名だけに結んでいた。同じ記録へ 2 つを同時に上げ、片方の変換が遅れる間にもう片方を保存して確かめると、遅れた方が同じ名に書かれて、確かめた写真が別の写真に差し替わり、確かめた扱いのまま公開に出た
- どうしたらいいか:
  - 保存: 名の番号と書き込みを、変換の後に置き場の鍵（media_review.media_lock）の中で決める。中身は隠した仮の名（.up-…）に書いてから os.link で名を作る（名が既にあれば失敗する排他の作成・上書きしない）。1 つの記録の上限（3 つ）も鍵の中で数え直す。名の形と順（m1・m2・m3）は前のまま（頁と控えの並びが名の順に頼るため）
  - 確認: 確かめた時の中身の要約（sha256）と大きさを review.json に残す。公開（public）・配信（shown_to）・AI の口（visible）・確認を待つ物（waiting）は、今の中身の要約と照らし、違えば確かめていない物として扱う（公開にも配信にも出さず、確認を待つ物に戻る）。動画は音を落とした後の中身で取る。要約は置き場の名・変えた時刻・大きさごとに覚え、頁を開くたびに読み直さない
  - 競合: 上げた画面の控え（claim の owners.json）・確認の記録（record・revoke）・取り下げ（records.withdraw の置き場の削除）を、同じ鍵で順に通す
  - 要約の無い前からの確認（この直しの前に確かめた物）は、前のとおり名で読む（前に確かめた物を頁から消さない）。保存が上書きしない形になったので、その名の中身もこの後は替わらない
- 見た事: 名を でたらめの名 にする案もあったが、頁と控えの並びが名の順（m1・m2…）に頼るので、名の形は替えずに、排他の作成と中身の要約で守った（見た目と挙動を替えない）
- ゴールの要件: `tests/test_media_content_bound.py`（変換を待たせて順を固定した同時の上げで別の名・確かめた中身は替わらず公開は確かめた中身だけ・中身が替われば出さずに待ちへ・要約が残る・前からの確認はそのまま・同時の 5 つで 3 つまで名が重ならない・控えが消えない）
