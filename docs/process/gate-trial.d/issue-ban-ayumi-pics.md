## 型紙の版の歩みの額に、repo の中から作れる版の絵を出す（直しの担当、issue/ban-ayumi-pics、11-07 夜）

- 目的: 玩具の頁の「型紙の版の歩み」の額に、版ごとの型紙の小さな絵を出す。作れない版は、空の額でなく「この版の絵は残っていない」と出す
- なぜか: 本人の見直し（11-07 22:16）「過去の版が表示されていない。」。額の絵は repo の外の置き場（out/history/sheets。エンジンが組ごとに出した絵を写す所）にだけあり、repo の clone で動く公開の場では全部の額が空だった
- どうしたらいいか（比べた案と推し）:
  - 推し: 置き場に無い絵は、repo の中から作れる版だけ作る。改善の輪より前の版（御来迎 v1〜v10・虎 v1〜v3）は、刷って渡した紙の PDF（docs/process/trials/sheets の仮説 A。v1〜v4 は仮説 A に当たる tab）の 1 枚目。今の版（御来迎 v14・虎 v7）は、今の雛形でたたき台を刷った 1 枚目。間の版は、engine/（#565 で入ったエンジン）の見本にその版の組の JSON がある版（御来迎 v13・虎 v5・v6）だけ、engine/ のエンジンで刷った 1 枚目。組の JSON も紙も無い版（御来迎 v11・v12・虎 v4）は字で残っていないと出す
  - 比べた案 1: エンジンが出した 21 枚の絵（repo の外の置き場）を小さくして repo に入れる。生成物を repo に入れない決まり（画像は NDL と東京学芸大学の PDM の物だけ）に当たるので採らない
  - 比べた案 2: 組の JSON の無い版も、今の雛形で刷り直す。その版の寸法ではないので、その版の紙として見せる事になり、採らない。この repo の履歴でも、御来迎は v10 から v14 へ飛び（v11〜v13 は来ていない）、虎の v5 も来ていない
  - 比べた案 3: 公開の場の作り直しで、エンジンが出した 21 枚を out/history に写す（kaizen_history copy）。公開の場には出るが、repo を clone した人には出ない。engine/ の見本で作れる 3 版はこの PR で作り、残る 3 版をどうするかは統括の決め
- 確かめた事: 改善の輪より前の版の PDF の 1 枚目は、エンジンが出した絵と同じ紙（縮めた絵の差の平均が 1 未満。ほかの仮説の紙とは 3 以上）。御来迎 v14 の今の雛形の紙も、エンジンが出した v14 と同じ形（差 1.9）。engine/ の見本を engine/ のエンジンで刷った紙は、エンジンが出した絵と同じ形（御来迎 v13 は 0.5・虎 v5 は 2.0・虎 v6 は 1.0）。虎 v7 は、エンジンが出した絵（11-07 10:36）と今の雛形の紙で題と並びが違う（今の雛形の紙を出す）
- ゴールの要件: 作れる版は img で、絵は幅 298 の PNG。作れない版は「この版の絵は残っていない」の字で、空の額は出さない。頁を返す時は絵を作らない（作るのは絵が求められた時）
- 検証ゲート: **済み**。Red: 今の main（654256ed）に tests/test_ban_ayumi.py だけを置くと、虎の額の絵が v7 だけで rc 1（gate-evidence/red-ban-ayumi-pics.txt）。Green: この枝で rc 0（green-ban-ayumi-pics.txt）。engine/ の見本の版を足した後: 前の作り（3afa99ec の kaizen_history と ban_ayumi）に今の main を取り込んだ木（23dd3927）で、虎の額の絵が v1〜v3・v7 だけで rc 1（red-ban-ayumi-engine.txt）、この枝で rc 0（green-ban-ayumi-engine.txt）
