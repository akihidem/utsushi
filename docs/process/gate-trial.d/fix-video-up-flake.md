## 動画の受け口の試験を、回す機械の本物の空きに頼らない形にする（直しの担当、fix/video-up-flake、11-07。合体の道の門）

- 目的: `tests/test_video_up.py` が、回す機械の空きが 40GB を切ると rc 1 で落ちるのを止める。試験の守る物（空きが足りない時は断る・途中で切れた小分けを届いた物に数えない・途中の物を残さない ほか）は変えない
- なぜか: 11-07 に 3 か所の作業の木で同じ落ち方をした（328 行の後片付けの rmdir が FileNotFoundError、その前に受け口の BrokenPipeError）。揺れではなく、回した機械の / の空きが 39G（97% 使用）で、受け口の空きの床 `MIN_FREE`（40GB）＋小分け 1 つを切っていたため。受け口はどの小分けも 507 で断り、途中で切れた小分けの置き場（tmp/<id>）を作らないので、後片付けで消す物が無かった。断りの返事を、もう閉じた口へ書いたのが BrokenPipeError
- どうしたか: 試験の頭で `video_up.MIN_FREE = 0` にする（小分けの大きさを小さくしている所と同じく、試験の中だけの値）。空きが足りない時に断る事は、今までどおり床を 10**18 に上げて 507 を見る所と、disk_usage を 0 にして見る所が守る
- 比べた案: 後片付けを `rmtree(ignore_errors=True)` にする案は、空きが足りない機械で「途中で切れた小分け」の見る所が、置き場の無いまま素通りで通るので採らない
- ゴールの要件: 空きが 40GB を切った機械で、直した試験を 20 回回して rc 1 が 0 回。試験の見る事（assert）は変えない
- 検証ゲート: **済み**。Red: 直す前の試験で rc 1（gate-evidence/red-video-up-free-space.txt）。Green: 直した木で 20 回とも rc 0。ただし回している間に機械の空きが 39G から 108G に増えた（ほかの作業の片付け）ので、shutil.disk_usage の空きだけを 39GB に見せかけた形でも 20 回回し、20 回とも rc 0（gate-evidence/green-video-up-free-space.txt）
- 気づき（直していない）: 公開デモの動画の受け口がこの機械で動くと、空きが 40GB を切っている間は動画を受けられない。空きの作り方は統括から本人へ
- マージ後の書き戻し: Issue は立てていない（新しい Issue は提出を止める物だけ）
