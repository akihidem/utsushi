## 話した考えから型紙を作り直す口の費用の止め 3 つ（Issue 対応の担当、issue/talk-sheet-guards、11-08）

- 目的: 型紙の窓に「Claude に話して型紙を作り直す」口を置く前に、その口が Claude を呼ぶ費用の止めを先に入れる
- なぜか: 本人の言葉（11-08・統括を通して）「版が若いものは、型紙を出力する前に、自分で仮説を話してよくしてから作りたいと思うと思う。型紙のところに、クロードに自分の考えを話して型紙を改善するボタンを設置して、再生成してもらうボタンをつけたい。」。設計は grove の state/tsukuru-talk-sheet-20261108.md（2 版・別の目の検品で PASS）。本人の答え（11-08）「1 日 30 回」
- どうしたらいいか（設計 2 版の 4 節の 3 つ）:
  - この口が Claude を呼ぶ 1 日の回数（budget.WORDS_PER_DAY = 30・日本の日付・全部の玩具と画面を合わせて）。達したら Claude を呼ばず、作る側の待ちにも置かず、今日の上限の字（BudgetStop.NOTES の day）で断る。数えるのは Claude を呼んだ記録（trace の有る W-番号）。呼べずに待ちへ落ちた回も、呼びに行った分の費用がかかりうるので数える
  - 予算の止め（BudgetStop: 今日の上限・累計の停止線・1 回の上限）は、作る側の待ちに落とさず、止めの字で断る（前は鍵なし・通信の失敗と同じ線で待ちに落ち、止めの字が出なかった）
  - 受け口 /toy/<印>/think-sheet と /think-ok を、書き込みの数の止め（play_server.WRITE_PATHS）に入れる（前は数の上限が無かった）
- 見た事: 最悪の見込みは、1 回の押しが 1 回の run で、run の上限 PER_RUN_CAP（3 ドル）まで使う形。日割り 50 ドルを 17 回ほどの押しで使い切り、聞く口・動画を見る口も止まる。手元の実測は words の 5 回で 0.108 ドル（最大 0.041）。30 回の止めは最悪でも 90 ドルではなく、日割りの止め（50 ドル）が先に効く（日割りの止めはこの枝で待ちに落とさない形になった）
