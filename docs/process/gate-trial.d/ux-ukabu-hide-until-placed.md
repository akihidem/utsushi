## 入口の浮かぶ玩具を、置き直すまで見せない（JS の無い画面と、開いた直後の一瞬の重なり）（README の担当、ux/ukabu-hide-until-placed、11-08）

- 目的: 本人の言葉（11-08）「iPadで横表示で見たら文字が重なってる。PC、iPhoneなどいろんな大きさで見ても崩れないようにして。」の続き。#665（字を測って置き直す）の後に、別の目が残りを 2 つ挙げた
- なぜか: 別の目の測り（11-08・main 743706e5 と #665 を重ねた木・本物の輪郭の絵）で、JS の効く画面は重なり 0。残りは次の 2 つ:
  - JS の無い画面（台本を切った Chromium）: CSS の vw・vh の置き場のまま英語の頁で重なる（1024×768 で 6223px²・1180×820 で 5869・1440×900 で 3881・320×568 で 104）
  - 2 回目に開いた時: 絵が手元の写しから先に来て、置き直す前の 30〜60ms は CSS の置き場のまま重なる（英語 1024×768 で 6174・日本語 390×844 で 958 の下へ送る印）
- どうしたか: `src/web/ukabu.py`
  - 浮かぶ玩具の層を見せずに始める（.ukabu の visibility:hidden）。置き直しの台本（PLACE_JS）が最初に置いた後に .placed を付けて見せる。JS の無い画面では飾りを出さない
  - 最初の置き直しは DOMContentLoaded の後（下へ送る印と、それを画面に留める台本の後）。台本も下へ送る印の後に置いた（`src/web/looks.py`）
  - 絵がまだ読めていない玩具は出さない。絵が読めた時と字の形が決まった時は、待たずにその場で置き直す（前は 80ms 待っていた）。画面の大きさが替わった時は、次に描く前（requestAnimationFrame）
- 比べた案: JS の無い画面のために CSS の置き場の表を大きさごとに足す案は、表に無い大きさでまた重なるので採らない（#665 と同じ理由）。飾りを出さない方は、#665 の「字を隠すより出さない方を採る」と同じ向き
- ゴールの要件: tests/test_ukabu_no_overlap.py に足した。読み込みから 1.5 秒後までの描くたびの重なり 0（描いた回を 3 回以上見る）・台本を外した頁（JS の無い画面と同じ形）では 4 つとも出ない・大きさの一覧に 320×568
- 検証ゲート: **済み**。Red: 今の main の ukabu.py と looks.py で rc 1（gate-evidence/red-ukabu-early-nojs.txt・日本語 390×844 の描いた 1〜3 回目に右下の絵が下へ送る印に重なる）。JS の無い形だけの Red: 開いた直後の確かめを外した写しで rc 1（gate-evidence/red-ukabu-nojs-only.txt・台本を外すと 4 つとも出る）。Green: rc 0（gate-evidence/green-ukabu-early-nojs.txt）
- エビデンスゲート: 入口・英語・やさしい日本語の関わる試験 17 本 rc 0（「測れない」0）。本物の輪郭の絵でも、字の重なりの見回りの測り（grove の state/no-overlap-20261108.md）で入口の重なり 0
- 限り: iPhone の Safari と iPad の実機では見ていない。JS の無い画面では浮かぶ玩具が出ない（字は隠れない）
