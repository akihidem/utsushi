## 入口の浮かぶ玩具を、置き直すまで見せない（JS の無い画面と、開いた直後の一瞬の重なり）・触って送っても跳ばない（README の担当、ux/ukabu-hide-until-placed、11-08）

- 目的: 本人の言葉（11-08）「iPadで横表示で見たら文字が重なってる。PC、iPhoneなどいろんな大きさで見ても崩れないようにして。」の続き。#665（字を測って置き直す）の後に、別の目が残りを 2 つ挙げた
- なぜか: 別の目の測り（11-08・main 743706e5 と #665 を重ねた木・本物の輪郭の絵）で、JS の効く画面は重なり 0。残りは次の 2 つ:
  - JS の無い画面（台本を切った Chromium）: CSS の vw・vh の置き場のまま英語の頁で重なる（1024×768 で 6223px²・1180×820 で 5869・1440×900 で 3881・320×568 で 104）
  - 2 回目に開いた時: 絵が手元の写しから先に来て、置き直す前の 30〜60ms は CSS の置き場のまま重なる（英語 1024×768 で 6174・日本語 390×844 で 958 の下へ送る印）
- どうしたか: `src/web/ukabu.py`
  - 浮かぶ玩具の層を見せずに始める（.ukabu の visibility:hidden）。置き直しの台本（PLACE_JS）が最初に置いた後に .placed を付けて見せる。JS の無い画面では飾りを出さない
  - 最初の置き直しは DOMContentLoaded の後（下へ送る印と、それを画面に留める台本の後）。台本も下へ送る印の後に置いた（`src/web/looks.py`）
  - 絵がまだ読めていない玩具は出さない。絵が読めた時と字の形が決まった時は、待たずにその場で置き直す（前は 80ms 待っていた）。題の間の幅が替わった時は、描く前に置き直す（下の ResizeObserver）
- 触って送ると跳ぶ（本人の言葉 11-08「トップページ、右下のツボが iPhone で触ると動く。」・本人の答え: 動いたのは浮かんでいるおもちゃの絵の徳利）:
  - なぜか: iPhone の Safari は送り始めると番地の帯が縮み、resize が起きる。前の台本は resize のたびに置き直し、画面に留めた下へ送る印（fixed）を送った後の位置で、
    玩具の元の位置を揺れの途中の箱（transform 込み）で測ったので、印を避けて動かしていた徳利が別の所へ跳んだ
  - どうしたか: 題の間の幅が替わった時だけ置き直す（本人の答えを統括が伝えた線「置き直しは幅か向きが替わった時だけ」）。幅は題の間の箱を ResizeObserver で見る
    （入口の決まりで使わないのは IntersectionObserver。無いブラウザは resize）。画面に留めた物は送る前の位置で、玩具は揺れる前の箱（offset*）で測る
    （送り始めた後に絵が届いて置き直しが走っても跳ばさないため）
  - 試した事と失敗: 送ったまま幅を替えて戻した時に同じ所へ戻る事も試験で見ようとしたが、この場の iframe は読み込みの後に描く回が来ず、幅を替えた直後の
    横のスクロールの帯が消えないまま測るので、徳利が 16px 上に置かれて揺れた（置き直しのたびの入り力を控えて、印の上の端が 780 でなく 765 に測られていた事を見た。
    帯の太さの 15px）。見込みを 2 つ外した（スクロールの帯の出入りで幅が替わる・スクロールの錨合わせ）。幅を替えた時は動いてよい所なので、その段は試験から外し、
    250ms 後にもう一度置き直す備えも、確かめられないので入れなかった。落ちた版の証拠: gate-evidence/green-ukabu-steady.txt・-2・-3（rc 1）。
    前の版の試験の Red: gate-evidence/red-ukabu-steady.txt・-2・-3（幅を替えて戻す段があった版）
- 比べた案: JS の無い画面のために CSS の置き場の表を大きさごとに足す案は、表に無い大きさでまた重なるので採らない（#665 と同じ理由）。飾りを出さない方は、#665 の「字を隠すより出さない方を採る」と同じ向き
- ゴールの要件: tests/test_ukabu_steady.py（新・白と暗い版・3 つの言葉・iPhone 320×568・375×667・390×844・430×932 と iPad 820×1180・1024×768 で、題の間を触って
  120px 送っても・送ったまま高さだけを 94px 縮めても（390×844 → 390×750 の形）置き直さず、戻した後も元の位置）。tests/test_ukabu_no_overlap.py に足した。読み込みから 1.5 秒後までの描くたびの重なり 0（描いた回を 3 回以上見る）・台本を外した頁（JS の無い画面と同じ形）では 4 つとも出ない・大きさの一覧に 320×568
- 検証ゲート: **済み**。Red: 今の main の ukabu.py と looks.py で rc 1（gate-evidence/red-ukabu-early-nojs.txt・日本語 390×844 の描いた 1〜3 回目に右下の絵が下へ送る印に重なる）。JS の無い形だけの Red: 開いた直後の確かめを外した写しで rc 1（gate-evidence/red-ukabu-nojs-only.txt・台本を外すと 4 つとも出る）。Green: rc 0（gate-evidence/green-ukabu-early-nojs.txt。触って送る直しの後も -4 で rc 0）。
  触って送る: Red は 1 つ前の commit 6fd0cb76 の台本で rc 1（gate-evidence/red-ukabu-steady-4.txt・320×568 で高さを戻すと徳利が 236,543 から 228,590 へ）。
  Green: rc 0 を 2 回（gate-evidence/green-ukabu-steady-4.txt）

  JS の無い画面では浮かぶ玩具が出ない（字は隠れない）。PC の窓の高さだけを替えた時は置き直さない。向きや窓の幅を替えた時は置き直して動く
