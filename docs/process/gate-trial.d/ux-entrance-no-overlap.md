## 入口の浮かぶ玩具の絵を、どの大きさの画面でも字と押す所に重ねない（README の担当、ux/entrance-no-overlap、11-08）

- 目的: 本人の言葉（11-08）「iPadで横表示で見たら文字が重なってる。PC、iPhoneなどいろんな大きさで見ても崩れないようにして。」
- なぜか: 浮かぶ玩具の置き場は CSS の vw・vh で決まっていて、画面の形で余白が替わる。測ると、英語の頁の幅 1024〜1440 で左上の絵が英字の 1 行に、右上の絵（猿）が副題に重なり、幅 375・390 で右下の絵が下へ送る印に重なった（白と暗い版・3 つの言葉）
- どうしたか: `src/web/ukabu.py` に置き直しの台本を足した。頁が開いた後に、題の間の字の行と押す所の箱を測り、CSS の位置で重ならなければそのまま、重なる時は CSS の位置にいちばん近い重ならない所へ動かす（揺れの分の間をとる）。どこにも入らない玩具だけ出さない。絵が読めた時・字の形が決まった時・画面の大きさが替わった時に置き直す
- 比べた案: 画面の大きさごとの置き場の表を CSS に足す案は、表に無い大きさでまた重なるので採らない。重なる時に全部を消す案は、本人の決め（入口の余白に浮かばせる）から離れるので採らない
- ゴールの要件: tests/test_ukabu_no_overlap.py（白と暗い版・日本語・やさしい日本語・英語・iPad の横 1024×768・1180×820・1366×1024 と縦 768×1024・820×1180・PC 1280×800・1440×900・1920×1080・iPhone 375×667・390×844・430×932 で、出ている絵が字の行と押す所に重ならない・幅の外に出ない・4 つのうち 3 つ以上が出ている）
- 検証ゲート: **済み**。Red: 直す前で rc 1（gate-evidence/red-ukabu-no-overlap.txt）。Green: rc 0（gate-evidence/green-ukabu-no-overlap.txt）。66 の頁のどれも 4 つとも出て、重なり 0
- エビデンスゲート: 入口・英語・やさしい日本語の関わる試験 15 本 rc 0。幅 1024×768 の英語の頁の絵を目で見た（猿は副題の下へ、左の人形は英字の下へ動いた）
- 限り: 台本が動かない場（JS を切った）では、前の CSS の置き場のまま
