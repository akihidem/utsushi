## 1. 作品の輪と、Claude の置き場所

作品の輪は「予想 → 型紙を刷る → 紙で作って試す → 記録と人の説明 → 版の間に Claude が案を出し人が採る → 次の版」。**まず返事をするのは紙**（[philosophy.md](philosophy.md)）。だから Claude は、まず版と版の間の工房に置いた。2026-11-04 に本人は、子どもも AI から直接返事をもらってよいと決めた（[J-013](decisions/J013-core-words.md) の決める点 2 の変更）。学ぶ人に直接返す口はまだ作っていない。

| 輪の段 | 誰が | Claude の役 |
|---|---|---|
| 予想を書く | 使い手 | しない。予想が無ければ Claude を呼ばない（床 F9.prediction） |
| 紙が応える | 紙 | しない。紙の返事が先 |
| 記録と説明 | 使い手 | しない。人の説明が先 |
| AI の返事 | Claude | 学ぶ人の記録と説明の後に、直接返してよい。成績にしない（11-04 の決定。口は未実装） |
| 版の間の案 | Claude（工房） | 仮説と寸法の案、記録の解釈の案、次の手の案 |
| 採る | 人 | しない。人が端末で番号を打つまで一覧に入らない |

## 2. 機能の選び分け

道具を 2 つの場所に分けた。**使い手の口**（言葉の仮説を寸法に写す）と、**作り手の工房**（仮説の案を作る）。

| 機能 | どこで | 何をさせるか | なぜこれを選んだか | 選ばなかった物 |
|---|---|---|---|---|
| Messages API（手書きの輪） | 使い手の口、輪の後半 | 言葉を寸法に写す。記録の解釈と次の手の案 | 道具 8 回・やり直し 2 回・1 回 $3 の上限で必ず止め、そこまでを人へ返すため。決定的な床に落ちたら理由を読ませて直させる | Tool Runner（上限と人の確定を自分で握れない） |
| Skill `backstage` | 作り手の工房 | 図と歌と記録から仮説と寸法の案を作る手順 | 工房は作り手が Claude Code で回す。手順を Skill にすれば clone した人の工房でも同じ手順になり、API の鍵が要らない | API だけで回す（作り手にも鍵が要る） |
| MCP サーバ `utsushi` | 作り手の工房 | 寸法の検査、図の拡大、前例、案の全体の検査 | API の輪と同じ決定的な道具を Claude Code から呼ぶ。道具の実装を 2 つ持たない | 道具を Skill の中のコマンドで呼ぶ（API の輪とずれる） |
| サブエージェント `second-eye` | 作り手の工房 | 案の言葉と根拠を、作った者と別の目で読む | 採点の言葉、推測の断定、見分けられない組は機械の床で拾えない。作った者は自分の案の癖に気づきにくい | 同じセッションで読み直す |
| フック（PostToolUse） | 作り手の工房 | 記録や台帳を直した直後に台帳の検査を回し、落ちたら Claude に返す | 根拠の文の照合と要約の一致は、直した直後でないと push の前まで見つからない | push の前だけ検査する |
| モデル | 全部 | 全部 Opus 5.5 | 本人の決定（[J-017](decisions/J017-runtime-model.md)）。**比べて選んだのではない**。選び分けない判断として書く | 段ごとの選び分け（本人が採らなかった） |

**同じ線を 2 つの道で守る。** 工房で Claude Code が作った案も、API が作った案も、同じ受付（`import-draft` と `generate`）に入り、同じ床にかかり、人が採るまで一覧に入らない。どこで作ったかは記録に残る。

## 3. 開発の運転の形

この作品は、本人が作る側のセッションに直接触れずに作った（[how-it-was-built.md](how-it-was-built.md)）。

| 役 | している事 |
|---|---|
| 本人 | 決める。線を引く。作品の考えを言葉にする。実物を見て評価する |
| 窓口（本人の個人エージェント、Claude のセッション） | 本人の言葉を作る側へ取り次ぎ、作る側の判断を本人へ届ける |
| 作る側（この Claude Code のセッション） | 調査、設計、実装、検査、記録。決められない事は推しを付けてキューに上げる |

運転の道具:

- **判断のキュー**: 作る側は、本人にしか決められない事だけを、推しと判断材料を付けたカードにして上げる。本人は窓口でカードに答える
- **記録の台帳**: 決定・調査・判断待ち・主張と根拠を JSON に持ち、表は描画する。根拠の文が今もファイルにあるかを試験が見る
- **push の門**: push の前に、秘密、公開範囲、生成物、文書の中の存在しないパスなどを機械で見る
- **凍結した基準**: 受け入れの基準を先に固め、変えた時は理由を記録する

**弱さも書く**: 判断待ちで止まった時間（最長 124 分）、取り違え、窓口の文と本人の言葉の境目が見えない事は、how-it-was-built.md に測って書いた。

### 開発の運転の形 — 本人は手元のチャットから作る側を運転した

本人は開発の間、作る側（この repo を作った Claude Code のセッション）の画面の前にいない。iPad のチャットで、本人の個人のエージェントである窓口（Claude のセッション）に話し、窓口が作る側へ言葉を運び、作る側が上げた判断を窓口が 1 件ずつ本人に見せる。作る側を立てる道具と、機械で YES/NO を決める検査は、作業環境の側の別のセッション（受け皿）が受け持った。

```
本人（iPad のチャット）
  │ 決める・線を引く・作品の考えを言葉にする
  ▼
窓口（本人の個人のエージェント・Claude のセッション）── 判断待ちのキュー（判断を 1 か所に並べる）
  │ tmux 越しに作る側の画面を読み、文を送る
  ▼
作る側（Claude Code・ハッカソン用のアカウント・この repo を作る 1 本のセッション）
  ▲
  │ 立てる道具・push の前の検査・毎時の自己点検
受け皿（作業環境の側の Claude のセッション）
```

#### Claude の機能と、選んだ理由（運転の側）

| 使った物 | 何に | なぜそれを選んだか |
|---|---|---|
| Claude Code の 1 本のセッション（作る側） | 調査・設計・実装・検査・記録のすべて | 作業を 1 か所に集め、判断だけを人へ回す。判断の往復は、待ちの時間として測った（`how-it-was-built.md` の「弱さ 1」） |
| 窓口（本人の個人のエージェント） | 本人の言葉を作る側へ運び、作る側の判断を本人へ 1 件ずつ見せる | 本人が PC の前にいなくても、iPad のチャットだけで決められるため |
| tmux（端末の窓を保つ道具） | 作る側を切れない場所で動かし、窓口が画面を読み・文を送る | 作る側が止まらず、窓口が画面越しに運転できるため |
| Remote Control | 作る側のセッションを、本人が手元の端末から直に覗く | 窓口を通さずに画面を確かめたい時のため。起動の時にオンにするのを決まりにした |
| 判断待ちのキュー | 作る側が上げた判断を、全文・選択肢・推しつきで 1 か所に並べる | 画面ごとに流れた問いが消えないため。本人は先頭から 1 件ずつ答える |
| 設定のフォルダを分けたセッション | 作る側だけを、ハッカソン用のアカウントで動かす | 本人の普段の作業環境の Claude と取り違えないため |
| 受け皿（作業環境の側の別のセッション） | 作る側を立てる道具、push の前の検査、毎時の自己点検 | 作る側の判断に任せず、機械で YES/NO を決める所を分けるため |

#### 機械で止める所 — push の前の検査と、毎時の自己点検

- **push の前の検査**: GitHub への push は、毎回 push の前の検査を通った物だけにした。11-02 の最初の push から 11-03 20:55 までに 32 回 push を試し、2 回は検査で止まって直してから上げた。検査の中身はこの repo には置いていない。
- **毎時の自己点検**: 作る側を立てる道具の試験と台帳を、LLM を使わずに毎時 1 回点検し、異常があった時だけ判断待ちのキューに上げた（11-03 20:55 までに 2 回。提出の日の正午に止める）。

#### 物語の一文

「Claude Code を作る側の 1 本に据え、人は判断だけをする。判断は 1 か所のキューに集め、PC の前にいなくても手元のチャットから運転できる形にした。決まりで止める所は、作る側の判断でなく機械に任せた。」
